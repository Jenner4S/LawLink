# LawLink 培训手册（2026-11-20）

适用：新员工入职培训、新所上线培训　配套：[使用手册](./USER-MANUAL-20261120.md)（操作速查）

> **培训目标不是「会点按钮」，是「知道系统在保护什么」。**
> 这套系统的每个硬门禁背后，都有一个真实会出事的场景。培训要把场景讲清，否则学员只会觉得系统难用。

---

## 一、分层培训矩阵

| 角色 | 必修 | 时长 | 结业标准 |
|---|---|---|---|
| **律师 / 助理** | 模块 A + B | 2 小时 | 能独立走完「收案→转案→办案→结案」 |
| **行政 / 归档** | 模块 A + D | 1.5 小时 | 能独立完成归档与借阅 |
| **财务** | 模块 A + C | 2 小时 | 能说清「两步实收」为什么不能省 |
| **管理员** | 模块 A + E | 3 小时 | 能完成首次配置并通过自检清单 |
| **全员** | 模块 0 | 30 分钟 | 知道哪些事做了会被审计 |

---

## 模块 0 · 为什么律师需要这套系统（全员，30 分钟）

**不要念功能清单。用一个真实场景开场：**

> 老张办了三年案子，客户信息记在自己微信里。他离职那天，所里丢了 40 个客户的往来记录、
> 12 个在办案件的进度、还有 3 份只在他电脑里的证据材料。
> 更要命的是：**没人说得清他代理过的对方当事人里，有没有和现在这个新客户冲突的**。

**引出三件事（这三件是系统存在的全部理由）：**

1. **人走了，案子还在** —— 客户、案件、材料在系统里，不在个人手里
2. **利冲靠记忆必出事** —— 全所自动比对，红标阻断收案
3. **谁动过什么要说得清** —— 链式审计，管理员也改不了

**结尾一句**：这套系统里所有的「麻烦」（不能改责任人、不能直接删账、归档后不能写），
都是为了让上面三件事成立。**你觉得麻烦的地方，正是它在起作用的地方。**

## 模块 A · 通用操作（全员必修，45 分钟）

### A1 · 建立正确的心理模型（10 分钟）

讲三个概念，**用反例讲**：

| 概念 | 反例（学员容易犯的错） | 正确做法 |
|---|---|---|
| 系统管理员 ≠ 什么都能看 | 「我是超管，为什么打不开这个案子」 | 超管只配系统；看案子要业务权限 |
| 审批权独立 | 「我改了密码还是批不了」 | 审批权在「审批权限组」里单独配 |
| 默认不批自己 | 「就我一个人，我批我自己怎么了」 | 单人执业要显式开「本人审批例外」 |

### A2 · 走向收案 → 转案（15 分钟，实操）

**演练**：每人建一条收案，当事人填自己名字 + 一个真实老客户名。

- 系统会**自动做冲突检索**，让他们看到结论
- **重点讲**：红色命中转不了案。现场演示一次「被拦住」
- 讲清「冲突预检」**不出结论**，只是自己查，不能替代正式检索

### A3 · 办案进程（15 分钟）

**演练**：在刚才的案件里加一个任务、改一次任务、写一条记录、删掉它。

- 讲清「未完成事项只在待办，已发生事项只在经办记录」
- **现场演示**：改责任人 → 被拦住 → 引导到事项责任面板
- 说明为什么：换人要接收方确认，否则交接会断

### A4 · 审计意识（5 分钟）

**念一遍会被审计的动作**：看证件号、看电话、导出卷宗、改案件、删记录、批申请、看审计本身。

**强调**：审计不是监视，是**保护**——将来客户投诉「你们泄露我信息」时，能证明谁看过。

## 模块 B · 律师专项（2 小时含 A）

### B1 · 结案门禁（20 分钟）

**现场演示一个「结不了案」的案件**，把门禁清单投屏，逐项说明：

```
程序未结束 / 事项未处置 / 保全仍生效 / 交接待承接 /
待确认款 / 待审批
```

**讲师要点**：这些不是系统的官僚主义，是**每个都对应一次真实的「结案后才发现」**。

### B2 · 归档即冻结（15 分钟）

归档后：不能写、不能改关联、不能加证据项。

**为什么要讲透**：很多人归档完还想补材料，被拦住会觉得系统死板。
正确答案是——**补充归档走独立流程**，不是放开历史案件写入。

**已知限制坦白**：此前有「已归档案件仍可增删关联」「仍可新增证据项」两个缺口，
在 2026-11-19 修复。培训时如实说，别装作一直没问题。

### B3 · 期限与提醒（15 分钟）

- 期限按规则算；**法定休假日顺延只提示，不替你改日期**
- 提醒走送达台账，能看到「该发没发」
- 讲清：**系统提醒不等于你不看日历的责任**。期限算错，责任在律师

### B4 · 常见误区答疑（10 分钟）

| 学员会问 | 标准答案 |
|---|---|
| 为什么不能改责任人 | 换人要接收方确认，否则交接断在半路 |
| 为什么删记录只能删自己的 | 卷宗是共同记忆，不能互相抹 |
| 为什么导入的历史案件不能直接改 | 归档/结案状态是事实，不是草稿 |
| 系统说「案件不存在」但我确定有 | 措辞刻意统一，可能是权限问题。找管理员 |

## 模块 C · 财务专项（2 小时含 A）

### C1 · 两步实收（30 分钟，最重要）

**这是全系统最容易被绕过、也最不能绕的规则。**

> **任何人登记的实收都先记「待确认」** —— 经办律师自己收的、主任自己收的、财务本人登记的，全都一样。
>
> 待确认状态下：不生成实收、不派生分成、不写时间线、不计入报表、不进工作台统计。

**为什么**：如果登记即生效，一次误填就会污染分成、报表、回款率，而这些**事后很难查清从哪来**。

**讲师必须演示**：财务自己登记一笔 → 它也是待确认 → 再由自己确认（权限允许时）。

### C2 · 核销与账龄（25 分钟）

- 实收 → 应收，可手工分配，可用「按最早到期自动填满」
- **演示一次超额核销被拒**（系统会报「超过未核销余额」）
- 账龄看板怎么读

### C3 · 更正而不是删除（20 分钟）

- 已入账不可直接删
- 更正走冲正 / 退回，**原记录保留**
- 讲清：`finance.correct` 与 `finance.settle` 是独立权限，不随系统管理身份获得

### C4 · 分成（15 分钟）

- 分成从实收派生（`commissionPlan` 按比例）
- 合计**不会超过基数**（系统保证比例合计 ≤ 100%）
- 已结算记录不可改，扣回有上限

## 模块 D · 行政 / 归档专项（1.5 小时含 A）

### D1 · 归档流程（30 分钟）

申请 → 门禁检查 → 审批（排除自审批）→ 生成归档号 → 归档记录

- **撞号怎么办**：系统会提示「归档号刚被占用，请再提交一次，会取新号」
- 讲清归档号规则（同年度同类别按顺序）

### D2 · 借阅（25 分钟）

申请 → 审批 → 限时可读（默认 30 天）→ 归还

**重点**：到期自动失效，**不靠人记得**。检索只能看到归档号/案号/案名（最小披露）。

### D3 · 卷宗导出（15 分钟）

导出 = 打包 manifest + 材料 + 记录 + 财务摘要。**每次导出有审计**。

## 模块 E · 管理员专项（3 小时含 A）

### E1 · 首次配置（60 分钟，实操）

按使用手册 1.3 的六步走完，**每步验收**：

| 步 | 路径 | 验收方式 |
|---|---|---|
| 岗位角色 | `/admin/roles` | 建一个只读角色，用测试账号登录确认看不到财务 |
| 团队 | `/admin/teams` | 建团队，确认成员能看到彼此案件 |
| 审批权限组 | `/admin/approval-permissions` | 配一类事项，用另一个账号确认能批 |
| 归档制度 | `/admin/archive-policy` | **不配就去试归档，确认被拦** |
| 期限规则 | `/admin/reminders` | 建一条期限，确认算出日期 |
| 文书模板 | `/admin/document-templates` | 用模板建文书，确认变量替换 |

### E2 · 隔离墙（30 分钟）

- 建墙 → 被点名的人列表消失、直访 404
- **演示写路径也被挡**（这是 2026-11-19 修的关键缺口）
- 坦白已知限制：**通知不按墙过滤**

### E3 · 审计与备份（45 分钟）

- 后台看审计链完整性卡片
- 导出一次 SIEM
- **备份不是可选项**：`./scripts/backup.sh`，以及 `scripts/drill-backup-restore.sh` 演练
- 讲清：自动迁移前会强制备份，备份失败会**中止部署**

### E4 · 部署与升级（45 分钟）

- 部署走 `./scripts/deploy.sh`
- 升级前必做：备份 → 副本演练 → 再动生产
- **已知环境问题**：`apk add` 间歇卡死，重试一次即可
- 数据层有两条破坏性改动（材料版本链唯一约束、撤销 previousHash 索引），升级前必须备份

## 二、结业考核（可执行，不是走过场）

### 律师岗（5 题，全对才算过）

1. 建一条收案，其中一方当事人与所在所有利冲 → **截图被拦的提示**
2. 在办案件里改责任人 → **截图被拦的提示，并说明正确做法**
3. 一个案件结不了案 → **列出卡在哪几项**
4. 归档后想补一份材料 → **说明正确路径**
5. 有人说「你上周看过我的客户证件号」→ **说明去哪查证**

### 财务岗（4 题）

1. 登记一笔实收 → **截图它处于待确认，并说明为什么报表看不到**
2. 尝试超额核销 → **截图被拒**
3. 已入账的一笔要改金额 → **说明正确做法（不是删除）**
4. 说明 `finance.confirm` 与 `finance.correct` 的区别

### 管理岗（5 题）

1. 完成首次配置六步 → **提交每步的验收截图**
2. 建墙并验证读、写两侧都被挡 → **两张截图**
3. 跑一次备份 + 一次恢复演练 → **提交演练日志**
4. 说出「通知不按隔离墙过滤」这个限制，并说明缓解办法
5. 说明升级前必须做的三件事

## 三、给讲师的三条提醒

1. **不要跳过「已知限制」**。隔离墙的通知不过滤、归档曾有的两个缺口——如实讲。学员发现你没说，会比限制本身更损害信任。
2. **每个门禁都要讲出场景**。只说「系统不让」会让人想办法绕过；讲清「为什么不让」才会配合。
3. **现场必须演示「被拦住」**。一次真实的拦截，比十页 PPT 有效。
