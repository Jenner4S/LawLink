# 客户门户：交互与界面设计（2026-11-20）

配套：[架构方案](./PORTAL-ARCHITECTURE-20261120.md)（身份/权限/数据模型）｜ [使用手册](./USER-MANUAL-20261120.md)

> 本文只写**用户看到什么、点哪里、看到什么状态**。
> 底层怎么隔离见架构方案；本文不重复。

---

## 一、设计原则（三条，冲突时按顺序取舍）

1. **客户看到的每一样东西，都必须是有人主动给的** —— 没有「默认可见」。
2. **客户界面上不出现内部用语** —— 不出现「隔离墙」「利冲命中」「审批组」「归档门禁」。
   客户不关心律所内部怎么管，只关心「我的案子进行到哪了」。
3. **宁可少给，不可给错** —— 拿不准的字段一律不展示。客户看不到不会投诉，看错了会。

---

## 二、信息架构

客户端只有四个一级入口，**再多就是负担**：

```
我的案件    —— 案件进度、已分享材料
我的账单    —— 已开票、待收款、发票下载
消息        —— 我提的问题与回复
（右上角）  —— 修改密码 / 退出
```

**没有**：日程、任务、审批、财务明细、客户管理、报表。这些是律所内部的事。

## 三、页面清单

| 路由 | 页面 | 数据来源 |
|---|---|---|
| `/portal/login` | 登录 | — |
| `/portal/activate?token=` | 首次激活设密码 | `PortalInvite` |

| `/portal/account` | 账号：改密码 | — |

## 四、关键页面设计

### 4.1 登录页 `/portal/login`

```
┌──────────────────────────────────┐
│        〔律所 Logo〕              │
│         客户服务门户              │
│                                  │
│  邮箱  [________________]        │
│  密码  [________________]        │
│                                  │
│        [   登 录   ]             │
│                                  │
│  忘记密码？请联系您的承办律师      │
└──────────────────────────────────┘
```

**设计要点**

- 不提供「忘记密码」自助重置 —— 客户邮箱未必可靠，走律师人工核对更安全
- 登录失败**统一文案**：`邮箱或密码不正确`。不区分「账号不存在」
- 连续失败 5 次锁定 30 分钟，提示：`尝试次数过多，请 30 分钟后重试或联系承办律师`
- **不显示**「本系统支持 Passkey / SSO」——客户不用这些

### 4.2 激活页 `/portal/activate?token=`

律师在客户详情点「邀请客户开通」→ 生成一次性链接发给客户。

```
┌──────────────────────────────────┐
│  设置您的登录密码                 │
│                                  │
│  邮箱   zhang@example.com        │（只读，来自邀请）
│  密码   [________________]       │（至少 12 位，含字母与数字）
│  确认   [________________]       │
│                                  │
│        [   开 通   ]             │
└──────────────────────────────────┘
```

**三种失败状态必须各有专门文案**（不能都显示「链接无效」）：

| 状态 | 文案 |
|---|---|
| 已过期 | `这个链接已过期（有效期 24 小时）。请联系您的承办律师重新发送。` |
| 已使用 | `这个链接已经用过。如果您已设过密码，请直接登录。` |
| 已撤销 | `这个链接已失效。请联系您的承办律师。` |

### 4.3 首页 `/portal`

**没有案件时**（空态是最容易被忽略的页面）：

```
┌──────────────────────────────────┐
│  还没有向您开放的案件             │
│                                  │
│  您的承办律师开放案件后会出现在这里。│
│  如需了解进展，可以 [提问]。       │
└──────────────────────────────────┘
```

> 空态必须说「为什么空 + 能做什么」。一句「暂无数据」是最差的做法。

**有案件时**（卡片列表）：

```
┌────────────────────────────────────────┐
│  张某某 诉 李某 民间借贷纠纷            │
│  案号 (2026)京0105民初12345号           │
│  ● 审理中 · 开庭 2026-12-03            │
│  最近更新 2026-11-18                    │
└────────────────────────────────────────┘
```

**不显示**：承办律师内部姓名（除非律所选择公开）、内部编号、费用明细、风险提示。

### 4.4 案件详情 `/portal/matters/[id]`

**只渲染白名单字段**，这是最重要的界面约束：

| 展示 | 不展示 |
|---|---|
| 案件名称、案号 | 内部编号 `internalCode` |
| 阶段名（立案/审理/判决） | 阶段内部状态、停留天数 |
| 开庭时间、法院 | 承办团队、协办人员 |
| 已分享的材料列表 | 未分享材料（**连名字都不出现**） |
| 承办律师（若律所开启） | 内部批注、策略分析、评估意见 |

**材料区**：

```
材料（3）
  起诉状.pdf              2026-10-12   [下载]
  证据目录.pdf            2026-10-20   [下载]
  一审判决书.pdf          2026-11-18   [下载]
```

> **未分享的材料连标题都不出现**。显示「另有 5 份材料未开放」都会引发追问，
> 而这 5 份里可能就有一份是「内部风险评估」。

**下载行为**：`/portal/api/documents/[id]`，实时校验 `PortalShare` + `revokedAt`。
未分享返回 **404**（不是 403）——403 等于告诉对方「这份存在但你不能看」。

### 4.5 账单 `/portal/bills`

```
┌────────────────────────────────────────┐
│  发票号 12345678                       │
│  金额   ¥ 30,000.00                    │
│  开票日 2026-10-20                     │
│  状态   已开具 · 待收款                 │
│                        [下载发票 PDF]   │
└────────────────────────────────────────┘
```

**关键约束**：这里显示的金额**必须与财务模块同一数据源**。
两处对不上，客户会拿着门户截图来对账——这是最伤信任的一类不一致。

### 4.6 提问 `/portal/requests`

```
┌────────────────────────────────────────┐
│  我的提问                    [+ 新提问] │
│                                        │
│  关于下次开庭需要准备什么材料           │
│  已回复 · 2026-11-19                   │
└────────────────────────────────────────┘
```

新建提问只需 **标题 + 正文**，不需要选案件（员工侧自己关联，避免客户选错）。

**回复时限**：员工侧看到工单时显示剩余时间；超期标红。客户侧**不显示**时限
（承诺了就要做到，做不到不如不承诺）。

## 五、员工侧配套界面

### 5.1 客户详情页新增「门户」卡

```
门户（已开通 · 1 个账号）
  张三  zhang@example.com  最后登录 2026-11-19
  [邀请新联系人]  [停用]
```

### 5.2 案件详情的「分享给客户」区块

放在「材料」区旁，**不放在顶栏**（顶栏只放主操作）：

```
□ 起诉状.pdf          [分享给客户]
□ 证据目录.pdf        [分享给客户]
☑ 一审判决书.pdf      已分享 2026-11-18 · [撤销]
```

**批量操作**：勾选多个 → 「分享所选」。撤销需 `confirmDialog` 确认。

**归档案件的分享按钮置灰**，提示：`案件已归档，不可再向客户披露新内容`。

### 5.3 工单待办

进员工侧「审批/待办」区，显示：
```
客户提问 · 张三 · 关于下次开庭…
剩余 1 个工作日  [回复]
```

## 六、状态设计（每个页面必须有四种）

| 状态 | 做法 |
|---|---|
| **加载** | 骨架屏，不用转圈（转圈让人以为卡住） |
| **空** | 「为什么空 + 怎么开始」（见 4.3） |
| **错误** | 「发生了什么 + 你能做什么」，不显示技术错误 |
| **无权限** | 一律 404，不提示「无权访问」 |

---

## 七、文案规范（对客户说话的方式）

| 场景 | ❌ 不要这样写 | ✅ 这样写 |
|---|---|---|
| 未分享材料 | 无权查看此文档 | （不出现） |
| 会话过期 | Session expired / 401 | 登录已过期，请重新登录 |
| 系统错误 | TypeError: Cannot read… | 系统暂时无法处理，请稍后重试或联系您的承办律师 |
| 案件已归档 | 状态机校验失败 | 本案已结案归档，如需补充材料请联系承办律师 |
| 登录失败 | 该邮箱未注册 | 邮箱或密码不正确 |

---

## 八、可访问性与响应式

- 客户端**必须能用手机打开**（这是客户的主要设备）。窄屏下卡片单列、表格横向滚动
- 所有可点元素 ≥ 44×44px
- 表单有 `<label>`，错误提示与字段关联（`aria-describedby`）
- 颜色不是唯一信息载体（状态用「文字 + 颜色」双编码）

---

## 九、这一版明确不做的交互

| 项 | 为什么 |
|---|---|
| 客户上传材料 | 上传是攻击面（恶意文件/超大文件）；第一阶段先不做，需要时走律师代传 |
| 客户在线支付 | 涉及支付牌照与资金归集，不是技术问题 |
| 客户即时聊天 | 工单够用；聊天会诱导客户期待实时响应 |
| 客户看工时明细 | 会引出「为什么这项要 3 小时」的争论，承办律师无法逐条解释 |
| 客户评价公开 | 评价只进内部看板，不对外展示 |
