## 阅读方式

每段给四行：**能做什么** / **在哪个页面** / **怎么验证** / **已知边界**。
「已知边界」写的是**能力到哪儿为止**，不是缺陷清单——缺陷在台账里。

## 一、获客

**能做什么**
- 线索登记：姓名/联系方式/微信/机构/**职业行业**/来源/渠道（两级）/券金额/案件类型/预估金额
- 手机号查重：归一化后跨**线索/客户/收案**比对，只提示不阻断
- 派单给律师：派单后状态 **待接单**，由律师**本人**接/拒/暂忙（拒接须理由，不自动转派）
- 二次对接人：与负责人分开记录，附交接时间
- 阶段推进：登记 → 邀约 → 到店 → 谈案 → 转收案
- 到店三态：未到店 / 已到店 / **爽约**（爽约不推进阶段，可再约）
- 漏斗与渠道：新增/邀约/到店/谈案/爽约/转收案 + 转化天数 + 按渠道单位成本 + **渠道下钻**（点渠道看它带来的线索，一级含子渠道）
- 渠道与口径设置：两级渠道增停（**停用不删除**）、风代计提基数、券金额归属、坏账自批上限、**列表列显隐**

**在哪个页面**：`/leads`

**怎么验证**
- 行内按钮走一遍：派单 → 接单 → 邀约 → 到店 → 谈案 → 转收案
- 顶部筛选切「待派单 / 待接单」，URL 变 `?assignee=...`
- `node scripts/acceptance-walkthrough.mjs`（15 项，含非本人接单被拒）

**已知边界**
- 同一手机号**不阻断**登记（家人代接、总机转接是真实场景）
- 渠道只做**两级**；三级归入二级的名称里
- 单位成本只算**成本**，不做 ROI 比率（缺收入侧可信数据）
- 列显隐按**所**生效（非按人）；**线索人列与操作列不可隐藏**；不做公式列/冻结列
- 线索列表顶部**登记表单**的渠道/来源是下拉（Radix），自动化点不了，需人工点一次

## 二、邀约与到店

**能做什么**
- 邀约登记：约定时间 + 跟进内容，进时间线可回看
- 到店登记：阶段推进 + 到店时间
- 爽约登记：独立记录，**不推进阶段**（还能再约）
- 提醒：邀约前提醒按 1/3/7 天档位登记进台账，到点投递
- 时间线：每次跟进（含接单/拒接）都留痕

**在哪个页面**：`/leads`（行内按钮 + 时间线弹窗）

**怎么验证**
- 点「邀约」→ 阶段变「已邀约」；点「未到店」→ 记爽约、阶段不变
- 打开时间线，能看 INVITE/VISIT/CONSULT 与接单痕

**已知边界**
- 爽约**不自动重排**下一次邀约（要不要自动重排是业务规则，未擅自加）
- 提醒走站内台账，**未接短信/微信**（需外部通道凭据）

---

## 三、到店谈案

**能做什么**
- 谈案完成登记（阶段 → 已谈案），**只有谈案后能转收案**
- 案件类型、预估金额、冲突检查（转收案前查利益冲突）
- 时间线记录每次沟通内容

**在哪个页面**：`/leads` → `/intakes`

**怎么验证**
- 未谈案直接点「转收案」→ **被拒**（金线反例已覆盖）
- 谈案后再转 → 生成收案单，收案联系人 = 线索名

**已知边界**
- 转化**只能从「已谈案」发起**（防跳步导致漏斗失真）

---

## 四、签约

**能做什么**
- 收案单 → 立案件（案件是收费、时间、材料、审批的挂载点）
- 合同/收费安排：金额、**风代比例**、签署状态
- 风代计提：只存比例，金额按**回款 × 比例**读时派生，界面标注「以结算单为准」
- 三角色分账：案源人 / 邀约人 / 面谈签约人（**同角色唯一**、合计 ≤100%、不足部分归所内）
- 冲突检查、审批链（用章、用印、特殊收费等）

**在哪个页面**：`/intakes` → `/matters/[id]`（委托与财务页签）、`/approvals`

**怎么验证**
- 案件详情登记合同 + 风代比例 → 出现风代明细块
- 分账对话框选三个角色 → 同角色重复选会被拒

**已知边界**
- **风代计提基数可配置**（默认按回款；改按合同额只需改配置，不改代码）
- 不足 100% **提示但不阻断**（余额归所内是行业做法）

## 五、回款

**能做什么**
- 应收/实收两步确认（**待确认到账不算已收**）
- 部分收款、退款（净实收 = 实收 − 退款）
- 坏账：申报 → **他人**审批（不能自批）→ 只扣未收余额，**不改写应收发生额**
- 坏账**逐笔冲抵**：申报时按最早到期优先自动分摊到具体应收条目并落明细，坏账面显示「冲抵 N 笔」（hover 看明细）
- 对账：`/finance/reconciliation`
- 发票与开票记录

**在哪个页面**：`/matters/[id]`（财务页签）、`/finance`、`/finance/reconciliation`

**怎么验证**
- 登记待确认到账 → 「已收」不变；确认后才计入
- 申报坏账 → 自己批准被拒；他人批准后未收余额下降、发生额不变

**已知边界**
- 坏账默认**双人复核**；`坏账自批上限` 可在「渠道与口径」配置（**默认 0 = 永不自批**，填 >0 时小于该金额可由申报人自批，审计记 `selfApproved`）
- 坏账逐笔明细与 `Allocation`（收款核销）是**两个方向**，不混用；完全无应收条目时允许合同级申报（先报后补）

## 六、报表

**能做什么**
- 营收/案件/客户/账龄等常规报表，按权限过滤可看范围
- 案件周期分析、复核问题分析、**满意度看板**（员工侧只读）
- 客户应收表含**已批坏账**列，余额与案件页同口径
- 导出 Excel

**在哪个页面**：`/reports`

**怎么验证**
- 切期间预设 → 数字随期间变
- 案件页批一笔坏账 → 报表该客户余额同步下降

**已知边界**
- 报表是**派生视图**；权威数仍在财务页与台账
- 单位成本/回款率的「率」在分母为 0 时显示「—」，**不显示 0%**

## 七、管理与风控

**能做什么**
- 用户与岗位、律师团队、岗位角色、审批权限、律所信息
- 期限规则库、归档制度、文书模板、阶段模板、自定义字段
- AI 与元典接入、快递接入、批量导入
- 审计日志（**不可删**，链式哈希校验）、隔离墙、邮件归档
- 数据留存：外部调用台账保留期（默认 365 天，可配 0=不清理）

**在哪个页面**：`/admin/*`（14 个页面，见左侧「管理后台」）

**怎么验证**
- `/admin/audit` 可按动作/对象筛；`/api/audit/export?format=json` 可导出（含完整性哈希）
- 改动任一业务数据 → 审计里能查到谁、何时、新旧值

**已知边界**
- 审计表**禁删**且当前**无自动归档**：一年约 15–22 万行、150–200MB；分区方案已实测可行（3 秒）但**建议等量级上来再做**
- cron 为**进程内**调度：单实例部署成立；多副本需数据库级租约（需迁移，未做）

## 八、协作与日程（支撑前述各段）

**能做什么**：案件日程、任务、期限、提醒台账、通知、公告、内部消息、材料与文书、用章台账、冲突检查、保全、归档与借阅、客户门户（查看进度/上传材料/工单/满意度）；客户档案含**职业**（2026-11-23 新增，与所属行业并存）

**在哪个页面**：`/schedule`、`/matters/[id]`、`/documents`、`/seals`、`/archive`、`/preservation`、`/conflicts`、`/portal/*`

**已知边界**：门户范围按既定决策实现（查看进度 + 上传材料 + 工单 + 满意度）；如需扩展到在线签约需另立需求。
