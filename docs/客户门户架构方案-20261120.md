# 客户门户与获客：架构方案（2026-11-20）

配套：[产品计划](./产品计划-20261120.md) ｜ [能力评估](./能力评估与缺口分析-20261120.md) ｜ [使用手册](./操作手册-20261120.md)

> 本文是**架构决策记录**，不是功能清单。每个决策写清选项、取舍、结论与代价。

## 一、现状约束（先读代码，再设计）

设计前实际核对的底座事实，全部有代码依据：

| 事实 | 出处 | 对设计的影响 |
|---|---|---|
| 认证栈全部围绕 `prisma.user` | `lib/auth/options.ts:303` jwt 回调每请求重读 User | 客户身份若复用 `User`，一处漏判就是全所泄露 |
| `getSession()` 按 `User.id` 查主键 | `lib/auth/session.ts:17` | 客户 id 查不到 → 会话自动失效（**碰巧安全，不能依赖**） |
| **项目没有 middleware** | 无 `src/middleware.ts` | 路由保护靠每个 layout/page 自己做，**门户必须自成一套守卫** |
| `requireSession()` 只认 `User.role` | `lib/auth/session.ts:36-45` | 客户会话若进到这里会被 `resolveRoleUser` 判定，行为不可预期 |
| 已有 194 个审计动作，链式哈希 | `src/server/audit.ts` | **新增字段会改变哈希输入** → 必须版本化处理 |
| 隔离墙/权限全部基于 `matterId` | `lib/permissions/*` | 客户维度不是「案件可见性」，是「客户归属」，两套正交 |
| 92 个 Prisma 模型，15 条迁移 | `prisma/schema.prisma` | 新表要纯增量，不改存量表结构（除可空列） |

**一句话约束**：这套系统的安全模型是「员工 + 案件可见性」。
客户门户引入的是**第二类身份**，它不是「权限更小的员工」。

## 二、五个架构决策

### 决策 1 · 客户身份：独立表，不复用 `User`

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A. 复用 `User` + `role=CLIENT`** | 一条认证路径；`sessionVersion` 复用；审计 `userId` 统一 | `User` 被 92 个模型引用，`assertCan*` 全假设是员工；`resolveRoleUser` 会按角色算权限 → **任何一处漏判，客户就能看到全所案件** |
| **B. 独立 `ClientPortalUser` 表** | 类型层面隔离（客户 id 不可能是 `User.id`）；`getSession()` 天然拒绝；审计可单独记 | 两套会话解析、两套登录页、失效逻辑要复制一份 |

**结论：B。**

**理由不是「更干净」，是「更安全」**：安全边界应当是**结构性的**。
选项 A 的安全性依赖「194 个审计动作 + 全部 Server Action 里每一处都记得判断这是客户」——
这种依赖在代码量增长后必然破功。B 让「客户会话碰不到员工通道」成为类型事实，而不是纪律要求。

**代价**：会话失效（`sessionVersion` 递增踢下线）要复制一份到门户侧；
测试要覆盖两条登录路径。

---

### 决策 2 · 材料可见性：默认不可见 + 显式分享

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A. 按分类自动开放**（如「判决书」「结案报告」自动给客户看） | 律师零操作 | 一份材料常含内部批注、策略备忘；分类是归档用的，不是披露用的 |
| **B. 显式分享**（律师逐个/批量勾选，落 `PortalShare` 表） | 默认不可见；撤销可审计；能回答「谁在什么时候把这份文件给了客户」 | 律师要多点几下 |

**结论：B。**

**铁律：门户里不存在任何「自动可见」的路径。**
没有 `if (category === ...) 可见` 这种规则。要看，就得有人点过「分享」，并且这个动作留在审计里。

**为什么这条不能妥协**：律所最贵的风险不是效率，是**不该给客户看的东西给了客户**。
一份带内部评估意见的案情分析发出去，可能直接输掉一个案子。

---

### 决策 3 · 权限检查：分享动作复用现有断言，读取用独立断言

- **分享（写）**：走 `assertCanHandleMatter` + `assertMatterWritable`
  → 只有能办这个案的人能分享；**已归档案件不可再分享**（归档即冻结）
- **门户读取**：走新的 `assertPortalCanRead(clientId, resource)`，只判「这条资源是否已分享给该客户」
  → **完全不查隔离墙、不查角色**——客户不在员工权限体系里

**为什么分开**：把两者混在一起，迟早会出现「客户借员工的权限读到东西」。

---

### 决策 4 · 审计：新增字段不参与哈希（关键风险点）

现有 `AuditLog` 是**链式哈希**，字段集合固定。直接加字段会让所有历史记录的哈希校验失效。

| 方案 | 结果 |
|---|---|
| 把新字段并入哈希输入 | ❌ 历史 601 条审计全部「被篡改」告警 |
| **新字段不参与哈希计算** | ✅ 历史链不受影响；新记录仍受链保护（哈希覆盖原有字段） |
| 做哈希版本号（v1/v2）并兼容 | 更严谨，但改动大 |

**结论：新字段（`actorKind`、`portalUserId`）不参与哈希。**

**代价如实记**：这意味着门户动作的「谁做的」这一维度**不在链式保护范围内**。
可接受的理由：门户动作只增不改，且 `portalUserId` 有外键约束；
但要写进文档，不能假装它也受保护。

**替代缓解**：门户侧单独一张 `PortalActionLog`（追加、含自校验），与 AuditLog 并行。

---

### 决策 5 · 路由与守卫：独立 `(portal)` 段，自带守卫

现状：没有 middleware，`(app)/layout.tsx` 只取 session 不强制跳转，各页自守。

**结论**：
- 新增 `src/app/(portal)/portal/*` 路由段，**有自己的 layout**，里面第一句就是 `requirePortalSession()`（无会话即 `redirect('/portal/login')`）
- **不引入 middleware**（引入会改变全站行为，风险远大于收益）
- 所有门户 Server Action 放在 `src/server/portal/`，**禁止与 `src/server/` 其他目录互相 import 业务写函数**，只允许 import 只读查询与 `audit`

## 三、数据模型草案

> 全部新表，不改存量（除 `AuditLog` 两个可空列）。迁移可整表回滚。

```prisma
// ── 身份 ──────────────────────────────────────────────
model ClientPortalUser {
  id             String   @id @default(cuid())
  clientId       String                     // ⚠️ 唯一绑定，一个人只能代表一个客户
  client         Client   @relation(fields: [clientId], references: [id], onDelete: Restrict)
  email          String   @unique
  name           String
  passwordHash   String
  active         Boolean  @default(true)
  sessionVersion Int      @default(0)       // 与员工侧同机制：递增即踢下线
  lastLoginAt    DateTime?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  invites   PortalInvite[]
  requests  PortalRequest[]
  ratings   PortalSatisfaction[]

  @@index([clientId])
}

// 邀请链接：一次性 token，24 小时过期
model PortalInvite {
  id          String   @id @default(cuid())
  portalUserId String
  tokenHash   String   @unique              // 只存哈希，不存原文
  expiresAt   DateTime
  usedAt      DateTime?
  createdById String                        // 员工 User.id
  createdAt   DateTime @default(now())
  portalUser  ClientPortalUser @relation(fields: [portalUserId], references: [id], onDelete: Cascade)
}

// ── 披露 ──────────────────────────────────────────────
// 唯一的可见性来源。没有这张表里的行，客户什么都看不到。
model PortalShare {
  id          String   @id @default(cuid())
  clientId    String
  shareType   PortalShareType               // DOCUMENT | MATTER_SUMMARY | INVOICE | BILLING
  documentId  String?
  matterId    String?
  invoiceId   String?
  sharedById  String                        // 员工 User.id
  sharedAt    DateTime @default(now())
  revokedAt   DateTime?
  revokedById String?
  note        String?
  @@index([clientId, shareType])
}

// ── 互动 ──────────────────────────────────────────────
model PortalRequest {
  id           String   @id @default(cuid())
  portalUserId String
  subject      String
  body         String
  status       PortalRequestStatus          // OPEN | ANSWERED | CLOSED
  answeredById String?                      // 员工 User.id
  answeredAt   DateTime?
  answerBody   String?
  dueAt        DateTime?                    // 时限（可配，默认 2 个工作日）
  createdAt    DateTime @default(now())
  portalUser   ClientPortalUser @relation(fields: [portalUserId], references: [id], onDelete: Cascade)
  @@index([status, dueAt])
}

model PortalSatisfaction {
  id           String   @id @default(cuid())
  portalUserId String
  matterId     String?
  score        Int                          // 1..5（NPS 用 0..10 另存 npsScore）
  npsScore     Int?
  comment      String?
  createdAt    DateTime @default(now())
  portalUser   ClientPortalUser @relation(fields: [portalUserId], references: [id], onDelete: Cascade)
}

enum PortalShareType { DOCUMENT MATTER_SUMMARY INVOICE BILLING }
enum PortalRequestStatus { OPEN ANSWERED CLOSED }

// ── AuditLog 增量（可空列，不参与哈希）──────────────
// actorKind  ActorKind @default(STAFF)
// portalUserId String?
```

## 四、安全设计（逐条对应真实攻击面）

| 攻击面 | 防护 |
|---|---|
| 客户 A 猜客户 B 的 id | 所有查询强制 `where: { clientId: session.clientId }`，**不接受前端传 clientId** |
| 客户猜 documentId 直取 | `assertPortalCanRead` 查 `PortalShare`；未分享一律 404（不是 403，避免枚举） |
| 客户调员工 Server Action | 员工侧 `getSession()` 按 `User` 主键查，客户 id 查不到 → 会话失效；**再加显式 `kind` 判定做双保险** |
| 客户暴力猜登录密码 | 复用 `login-lockout` 机制，独立计数表 |
| 客户上传恶意文件 | 门户**第一阶段不支持上传**；如后续要，走 `validateUploadedFile` + 加密存储 |
| 分享后反悔 | `revokedAt` 立即生效（读取实时判定，不靠缓存） |
| 归档后仍能分享 | 分享前 `assertMatterWritable` 拦截 |
| 会话被盗 | `sessionVersion` 递增踢下线 + 短 TTL；不做「记住我」 |
| 越权枚举客户 | 登录失败一律同一文案，不区分「邮箱不存在/密码错」 |

## 五、迁移与回滚

| 项 | 做法 |
|---|---|
| 迁移类型 | **纯增量**：6 张新表 + 2 个枚举 + `AuditLog` 两列（NULL 可空） |
| 回滚 | 新表可 `DROP`；`AuditLog` 两列保留（可空，不影响旧代码） |
| 备份 | 迁移前强制 `./scripts/backup.sh`（`deploy.sh` 已强制） |
| 演练 | 先在临时库 `migrate deploy` + 跑不变量 15 条 |
| 灰度 | 门户路由独立段，未配置即 404；不影响现有 `(app)` |

**风险等级：中**。新表不改存量语义，但 `AuditLog` 加列需要验证不影响链式校验。

## 六、分期实施（每期可独立交付、独立验收）

### S1 · 身份与登录（2 周）

| 交付 | 验收判据 |
|---|---|
| `ClientPortalUser` / `PortalInvite` 表 | 迁移在临时库通过；不变量 15 条不破 |
| 邀请 → 设密码 → 登录 | 真库测试：邀请过期/复用/撤回应分别失败 |
| 门户 layout 守卫 | 无会话访问 `/portal/*` 全部 302 到登录 |
| 员工侧「邀请客户开通」入口 | 客户详情页有按钮；动作写审计 |
| **客户会话不能调员工动作** | 测试：用客户 token 调 `getMatterById` 必须失效 |

### S2 · 只读视图（3 周）

| 交付 | 验收判据 |
|---|---|
| 案件进度（不含内部分析） | 只渲染白名单字段 |
| 已分享材料下载 | 未分享一律 404；撤销后立即失效 |
| 账单/应收摘要 | 只显示已开票与待收，不显示内部统计 |
| 分享/撤销 UI（员工侧） | 批量分享；撤销写审计 |

### S3 · 工单与满意度（2 周）

| 交付 | 验收判据 |
|---|---|
| 客户提工单 → 员工待办 → 回复 | 时限超期在员工侧标红 |
| 结案后邀评 | 一案件一次；匿名选项 |
| 满意度看板 | 员工侧只读看板 |

### S4 · 获客（5–8 周，可选）

见产品计划阶段 3。**建议 S1–S3 稳定运行 1–3 个月后再启动**——
没有真实的客户使用数据，获客模块做出来是空表。

## 七、未决问题（需要你拍板，我不代替决定）

1. **客户能不能看到「进度百分比」还是只看「阶段名」**？
   —— 百分比会引出「为什么一周没动」的追问，阶段名更安全。
2. **账单给不给金额**，还是只给「已开票/待收款」状态？
   —— 给金额会让客户拿它和发票对账，口径必须与财务一致。
3. **一个客户多个联系人，是否各自一个账号**？
   —— 建议：可以，但共享同一 `clientId`，互相能看到对方提交的工单（同一客户内部透明）。
4. **门户要不要支持中文以外的语言**？
   —— 建议不做（目标客户全中文）。
5. **S1 上线前是否要先做渗透测试**？
   —— 建议做。这是我第一次给系统加「外部可访问的入口」，风险性质变了。

## 八、我必须坦白的三件事

1. **这是本项目第一个面向外网的入口。** 之前的攻击面是「员工之间的越权」，
   现在是「陌生人对着登录框」。威胁模型变了，测试深度要求也要变。
2. **`AuditLog` 新字段不受链式保护**（决策 4）。文档里写清楚，不粉饰。
3. **客户身份的密码策略、重置流程、邮箱验证都要重新做一遍**——
   员工侧已有的那套（`passkey`/`totp`/`login-lockout`）直接搬过来是错的：
   客户不会装 TOTP，也不会接受一次性密码。**这部分成本我可能低估了。**
