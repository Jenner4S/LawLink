## 第 1 章 · 开始使用

### 1.1 登录

| 方式 | 条件 |
|---|---|
| 邮箱 + 密码 | 默认，管理员建号后给你初始密码 |
| Passkey（指纹/面容） | 需先登录后在个人资料里绑定 |
| 单点登录（SSO） | 需管理员先在 `/admin/ai` 配置企业 IdP |

**第一步永远是**：登录后进 `/settings/profile` 改初始密码。

登录失败 **5 次**会锁定，**15 分钟**后自动解锁（`lib/auth/options.ts:16-17`）。
失败提示不区分「账号不存在」与「密码错」——这是刻意的，避免账号枚举。

### 1.2 必须先建立的三个概念

| 概念 | 说明 | 你会遇到的场景 |
|---|---|---|
| **系统管理员 ≠ 业务权限** | 超管能配系统、管账号，但**看不到案件和财务** | 「我是超管，为什么打不开这个案子」 |
| **审批权是独立授予的** | 能不能批某类事项，由 `/admin/approval-permissions` 单独配 | 「我改了密码还是批不了」 |
| **默认禁止批自己** | 你提交的申请，你自己批不了 | 「就我一个人，我怎么批」→ 需管理员开「本人审批例外」 |

### 1.3 界面结构

```
┌─ 顶栏：冲突预检 | 新建收案(主按钮) | 法院短信 | 通知铃 | 用户卡
├─ 侧栏：工作台 / 案件 / 审批 / 日程 / 客户 / 财务 / 报表
│        └ 底部：更多应用（工具抽屉）
└─ 主区：当前页面
```

**主按钮只有一个**：顶栏的「新建收案」。其他操作在页面内。

### 1.4 管理员首次配置（顺序不能乱）

| 步 | 路径 | 做什么 | 不做的后果 |
|---|---|---|---|
| 1 | `/admin/roles` | 建岗位角色、勾权限 | 所有人都只能用内置角色的默认权限 |
| 2 | `/admin/teams` | 建团队、加成员 | 无法按团队共享案件 |
| 3 | `/admin/approval-permissions` | 配每类事项谁能批 | 没人能批，流程卡死 |
| 4 | `/admin/archive-policy` | 配置归档制度 | **不能正式归档**（硬拦） |
| 5 | `/admin/reminders` | 确认期限规则库、录放假安排 | 期限算出错误日期 |
| 6 | `/admin/templates` | 环节模板 | 新建案件不带环节 |
| 7 | `/admin/document-templates` | 文书模板 | 只能手写文书 |

**第 4 步是硬门禁**：没配归档制度，提交归档会被直接拒绝，不是提示。

## 第 2 章 · 核心业务全流程（逐步操作）

### 2.1 流程总览

```
① 收案登记 → ② 冲突检索（自动） → ③ 转正式案件
     → ④ 办案（程序/环节/事项/材料/记录）
     → ⑤ 财务（委托合同 → 应收 → 实收 → 核销 → 开票 → 分成）
     → ⑥ 结案 → ⑦ 归档 → ⑧ 借阅/导出
```

### 2.2 ① 收案登记

**谁做**：持 `intakes.create` 的律师/助理

**步骤**

1. 顶栏点 **新建收案**
2. 填：来源、联系人、初步案情、当事人（我方 / 对方 / 第三人）
3. 当事人是自然人：选证件类型（默认居民身份证），输入只允许数字与末位 X，限 18 位
4. 当事人是单位：录入名称后系统会尝试匹配工商信息，自动回填信用代码/地址/法定代表人
5. 提交

**提交后会发生什么**

- 系统**自动带全部主体做冲突检索**，结论挂在这条收案上
- 结论三种：可承接 / 有冲突 / 信息不足
- 收案进入 `/matters?tab=intake`（收案中）

**想先自己查一下**：顶栏 **冲突预检**。
> 它**不出结论**、不能替代正式检索、页面不保留历史预检记录（只在审计里留痕）。
> 用途是：收案前先摸个底。

### 2.3 ② 冲突检索结论怎么看

| 结论 | 含义 | 下一步 |
|---|---|---|
| **可承接** | 未命中，或命中已排除 | 可以转案 |
| **有冲突** | 有红色命中 | **必须**解除或走审批，否则转不了案 |
| **信息不足** | 主体信息不全，命中无法判定 | 补全主体后重新检索 |

**命中分级**

| 级别 | 处理 |
|---|---|
| 红色（BLOCKING） | 阻断收案，必须处理 |
| 橙色（HIGH） | 需审批 |
| 灰色（LOW） | 仅提示 |

**归一化命中的特别提示**：如果系统标注「请人工核对」，说明是按名称归一（去括号、去组织形式后缀、全角转半角）匹配上的，
不是逐字相同。**必须人工看一遍**，不要因为级别低就跳过。

### 2.4 ③ 转正式案件

**步骤**：在收案详情点「转为案件」

**系统会做**：生成统一编号 `internalCode`（全所财务、归档都认这一个号）

**会被拦住的情况**

- 冲突结论不是「可承接」
- 收案还有待补正事项

### 2.5 ④ 办案（案件详情）

进入 `/matters/[id]` 后，界面是**一屏工作台**：

```
┌─ 案卷头（案名、案号、状态、当事人摘要）
├─ 程序栏（浅色卡片，点击切换程序；末尾「＋ 添加程序」）
├─ 页签：案件档案 | 办案进程 | 委托与财务 | 审批用印
└─ 侧栏：承办团队 | 最近待办 | 最近记录 | 利益冲突复核（仅待复核时出现）
```

#### 2.5.1 添加程序

程序栏末尾 **＋ 添加程序** → 选类型（诉讼/仲裁/非诉等）→ 填法院、案号、承办人。

> 添加程序会触发**动态复核门禁**：如果案件主体或代理范围变了，会要求先重新做冲突检索。

#### 2.5.2 添加环节

「办案进程」页签左列末尾 **＋ 添加环节**。环节是组织事项的容器（如「立案」「举证」「开庭」）。

> 已有任务或材料的环节被「移除」时只是隐藏，数据保留，重新添加同名环节可恢复。

#### 2.5.3 添加事项（任务/期限/开庭）

「办案进程」→ **＋ 事项** → 选类型：

| 类型 | 必填 | 说明 |
|---|---|---|
| 任务 | 标题 | 进待办 |
| 期限 | 标题、类别、到期日 | 按规则可自动算日期 |
| 开庭 | 时间、法庭 | 进日程 |

**期限的自动计算**：选规则（如「一审举证期限」）后填触发日，系统按规则算到期日，**并把计算结果与你的输入做比对**。
不一致时会标注「系统按规则重算为 X，请核对」——**不强行改你的日期**，但你要看见。

**法定休假日顺延**：系统只给**提示**，不替你改日期。因为个案可能有例外（法院指定期间、当事人另有约定）。

#### 2.5.4 添加记录（沟通/寄收件/研判）

「办案进程」→ **＋ 记录**

| 类型 | 进哪 | 能否改删 |
|---|---|---|
| 沟通记录 | 经办记录 | **仅作者本人**可改/删 |
| 研判笔记 | 经办记录（标「人工判断」） | 仅作者本人 |
| 寄收件 | 经办记录 | 填单号后由接口更新状态 |

**改/删记录**：在记录行右侧。**只有你自己写的记录才显示这两个按钮**——卷宗是共同记忆，不能互相抹。

#### 2.5.5 修改任务

待办行右侧 **改** → 可改标题、说明、截止时间、优先级。

**改不了责任人。** 换人必须走「事项责任面板」：
```
事项责任面板 → 选人 → 发起交接 → 接收方接受 → 生效
```
> 为什么这么麻烦：没人接收的交接等于断在半路，而律师离职交接断掉是真实会出事的场景。

#### 2.5.6 上传材料

「办案进程」→ 材料区 → 上传。
- 支持多版本，改过几版看得见
- 文件加密存储
- 证据要点作为标签挂在材料行上，不单设证据链模块

#### 2.5.7 当事人

「案件档案」页签 → 当事人区，**我方在上、对方在下**，中间「诉 / 辩」圆标分隔。

### 2.6 ⑤ 财务流程

> 这一段是系统**约束最密**的地方。每个约束都对应一次真实踩过的坑。

#### 2.6.1 委托合同与补充协议

「委托与财务」页签 → 新增委托合同（Billing）：填合同额、签署日期、收费方式。

**补充协议**分五种，**不是简单相加**：

| 类型 | 效果 |
|---|---|
| 追加（ADDITION） | 合同额 + 金额 |
| 调减（REDUCTION） | 合同额 − 金额，**必须指定减少哪条应收** |
| 替代总价（REPLACEMENT） | 合同额 = 新金额 |
| 仅范围变更（SCOPE_ONLY） | 合同额不变（金额必须为 0） |
| 终止结算（TERMINATION） | 按终止日期结算 |

**生效条件**：约定生效日期未到不能生效；追加/替代/范围变更会触发**动态复核门禁**。

#### 2.6.2 应收

签署合同时自动生成，或手动登记。应收有「款项性质」（律师费/代收款等），**核销时性质必须相同**。

#### 2.6.3 实收（**两步，无人例外**）

```
第 1 步：登记   → 状态：待确认（琥珀色）
                 此时：不生成实收、不派生分成、不写时间线、不计报表、不进工作台
第 2 步：确认   → 需「确认实收到账」权限（finance.confirm，仅 ALL）
                 确认后才真正生效
```

**谁都要走这两步**：经办律师自己收的、主任自己收的、财务本人登记的，**全都一样**。

> 如果登记即生效，一次误填就会污染分成、报表、回款率，而这些事后很难查清来源。

**退回**：确认人可「退回」，系统删除该条 + 写审计 + 通知登记人。

#### 2.6.4 核销（实收 → 应收）

`/finance/reconciliation` → 应收与收款页签

1. 选一笔实收 → 分配
2. 选目标应收 → 填金额
3. 可用「按最早到期自动填满」生成建议 → 预览 → 确认

**会被拒的情况**
- 超过该实收未核销余额
- 超过该应收未核销余额
- 应收已作废
- 应收与实收不属于同一案件

#### 2.6.5 开票

**开票不以收款为前提。**

```
提交开票申请（关联案件须传开票依据；专票校验购方六要素）
   ↓
审批人二选一：
   A. 直接上传电子发票 + 填发票号 → 一步到「已开具」
   B. 先批准（待开票）→ 由持「执行开票」权限的人上传完成
```

**退回**：审批人可驳回并填写理由。

#### 2.6.6 分成

分成从实收派生，按分成方案（`CommissionPlan`）的比例。

- 系统保证**比例合计 ≤ 100%**，所以分成合计不会超过基数
- 结算（支付/扣回）需 `finance.settle` 权限
- 已支付不可改，扣回有上限（超过未支付额的扣回会被拒）

#### 2.6.7 更正

**已入账不能直接删。**

| 场景 | 做法 |
|---|---|
| 金额记错 | 提交财务更正 → `finance.correct` 权限人确认 |
| 收款退回 | 走退回流程，原记录保留 |

### 2.7 ⑥ 结案

案件详情 → 状态操作 → 结案。

**结案门禁会逐项检查**：

```
□ 程序是否都已结束
□ 任务 / 期限 / 开庭是否都已处置
□ 保全是解除还是仍生效
□ 交接待承接
□ 待确认实收
□ 待审批申请
```

有一项不过就结不了案。系统会列出**卡在哪几项**。

### 2.8 ⑦ 归档

1. 结案后 → 提交归档（需 `archive.submit`）
2. 系统检查归档制度是否已配置（**未配直接拒**）
3. 审批（复用 `ARCHIVE_APPROVE` 规则，**排除自审批**）
4. 生成归档号 → 归档完成

**归档号撞号**：提示「归档号刚被其他同事占用（同年度同类别按顺序编号）。请直接再提交一次，系统会取新号。」

**归档即冻结**：
- 不可再写案件
- 不可增删关联关系
- 不可新增证据项
- 不可再向客户分享（门户上线后）

**补充归档**：归档后需补材料 → 走「追加归档材料及补充归档」（`archive.supplement`），**不是**放开历史案件写入。

### 2.9 ⑧ 借阅与导出

#### 借阅（历史卷宗）

`/archive` → 借阅面板 → 申请（填事由）→ 审批 → 限时可读（默认 30 天，可 1–180）

- **到期自动失效**，不靠人记得
- 检索只能看到归档号/案号/案名（最小披露）
- 审批排除自审批

#### 导出

| 导出什么 | 入口 | 权限 |
|---|---|---|
| 案件列表 | 案件列表 → 导出 | `matters.export` |
| **单案卷宗打包** | 案件详情 → 导出卷宗 | `matters.export` |
| 归档材料 | `/archive` | `archive.read` |
| 报表 | `/reports` → 导出 | `reports.export` |
| 财务 | `/finance` → 导出 | `finance.read` |
| 审计 | `/admin/audit` → 导出 | 系统管理员 |

**每次导出都有审计留痕。** 导出卷宗等于把整个案卷带走，请当真。

## 第 3 章 · 按角色的日常操作

### 3.1 律师 / 助理

**每天早上**
1. `/` 工作台看：今日开庭、逾期事项、快到期
2. `/schedule` 看本周日程

**办案时**
- 沟通完 → 「＋记录」（选沟通渠道，填内容）
- 有新活 → 「＋事项」→ 任务
- 收到法院材料 → 上传到对应环节
- 开庭前 → 确认期限已算对

**注意**：写记录要一次写清楚。虽然能改，但改记录会写审计，卷宗里能看到修改痕迹。

### 3.2 财务

**每天**
1. `/finance` 看「待确认实收」——**这是最优先的事**，因为不确认就不进报表
2. 确认或退回，退回必须能说清理由
3. `/finance/reconciliation` 处理核销

**开票**
- 收到申请 → 看开票依据齐不齐
- 齐了 → 批准；能直接开 → 上传发票一步到位

**月底**
- 核对账龄
- 分成结算（`finance.settle`）
- 有记错的走更正，**不要想着删**

### 3.3 行政

| 事 | 在哪 |
|---|---|
| 快递登记 | `/express`，填单号后状态由接口更新 |
| 用章申请 | `/seals` |
| 律所公共资料 | `/firm-resources`（需 `firm-files.manage`） |
| 公告 | `/announcements`（需 `announcements.manage`） |
| 外部联系人 | `/contacts`（需 `contacts.manage` / `contacts.review`） |
| 归档台账 | `/archive`（需 `archive.read`） |

### 3.4 管理员

**每周检查**
1. `/admin` 首页看配置缺口警示
   - 无 `finance.confirm` 持有者且有款待确认 → 红
   - 无 `finance.tail` 持有者 → 黄
2. `/admin/audit` 看审计链完整性卡片有无断点
3. `/admin/reminders` 看送达台账有无积压或失败

**每月**
- 备份与恢复演练：`./scripts/backup.sh` + `scripts/drill-backup-restore.sh`
- 检查离职人员账号是否停用

## 第 4 章 · 跨模块功能

### 4.1 隔离墙（敏感业务必用）

`/admin/ethical-walls` → 新建墙 → 选案件 + 点名被隔离的人

**效果**

| 侧 | 表现 |
|---|---|
| 读 | 案件列表消失，直访返回 **404**（不是 403） |
| 写 | **同样被挡**——读不到也改不了 |
| 审批工作台 | 该案件的申请不出现 |

**已知限制（必须知道）**：**通知不按隔离墙过滤**。被隔离的人可能收到提到该案件标题的通知。
敏感案件请同时关闭相关通知，或调整通知接收人。

### 4.2 法院短信收件箱

`/inbox` 或顶栏「法院短信」

1. 粘贴短信内容（或由外部接入）
2. 系统尝试取件、阅读、生成建议
3. 「整理建议」区：逐条「采用 / 拒绝」或「全部确认」
4. 采用后：更新程序案号/法院、建开庭、建期限、更新归属

**文件状态**：待OCR / 已识别 / 需人工取件 / 待匹配 — 都是**可见状态**，不会假装成功。

**注意**：缴费类通知**只建待办，不自动记财务**。

### 4.3 日历订阅

`/schedule` 右上角「订阅日历」→ 复制链接 → 加到手机/Outlook

**是单向的**：系统改了会同步过去，你在手机上加的事项不会回到系统。

### 4.4 审计

`/admin/audit`

- 按对象查（已加索引，快）
- 链式完整性卡片：有断点会指出从哪来
- 导出：CEF / Syslog / JSON 三格式

**审计不是监视，是保护**——客户投诉「你们泄露我信息」时，能证明谁看过。

## 第 5 章 · 被拦住怎么办（故障对照表）

| 症状 | 真实原因 | 怎么办 |
|---|---|---|
| 「案件不存在」 | 真不存在 **或** 被隔离/无权 | 措辞刻意统一（不泄露案件存在性）。找管理员确认权限 |
| 实收登记了但报表没有 | 待确认状态不计入 | 找财务确认 |
| 改不了责任人 | 设计如此 | 走事项责任面板交接 |
| 归档按钮灰的 | 归档制度未配 / 结案门禁未过 | 看门禁清单哪项没清 |
| 批不了某个申请 | 审批组没授权 / 是本人申请 | 找管理员，或开「本人审批例外」 |
| 结不了案 | 门禁清单有未清项 | 按提示逐项处理 |
| 归档后想补材料 | 归档即冻结 | 走「追加归档/补充归档」 |
| 期限算出日期和我知道的不一样 | 系统按规则算，可能未考虑个案例外 | 系统只提示不顺延，**以法院通知为准**，可手工调整 |
| 登录后什么都看不到 | 账号没授业务权限（系统身份≠业务权限） | 找管理员配岗位角色 |
| 部署时卡在 `apk add` | Docker 构建网络问题（已知） | **重试一次** |
| 页面 500 但测试全绿 | 可能 `prisma generate` 产物被覆盖 | 重跑 `npx prisma generate` 并重启 |

## 第 6 章 · 数据安全与合规须知

1. **证件号、电话加密存储**，每次查看写审计。不要截图外传。
2. **导出卷宗有审计**，导出记录会被查。
3. **不要共用账号**——审计按账号记，共用等于审计失效。
4. **离职必须停用账号**，不是改密码。停用会让会话立即失效。
5. **备份不是可选项**：`deploy.sh` 在自动迁移前会强制备份，备份失败会中止部署。

## 附录 A · 门禁速查

| 门禁 | 拦什么 |
|---|---|
| 冲突阻断 | 红色命中未解除 → 不能转案 |
| 动态复核 | 主体/范围变更后 → 须重新检索 |
| 两步实收 | 登记不等于生效 |
| 核销不超额 | 超过余额 → 拒 |
| 分成不超基数 | 比例合计 > 100% → 拒 |
| 结案门禁 | 六项检查 |
| 归档冻结 | 归档后全部写操作禁止 |
| 责任人交接 | 必须接收方接受 |
| 隔离墙 | 读写双拦 |
| 自审批排除 | 本人申请不能自批 |
| 归档制度 | 未配不能归档 |

## 附录 B · 权限自查

点不到某功能时，按这个顺序查：

1. 我的**岗位角色**有没有这个权限键？（`/settings/profile` 看角色，`/admin/roles` 看该角色的权限）
2. 权限的**范围**够不够？（OWN 只能看自己经办的）
3. 是不是**系统管理身份**的问题？（配系统需要超管）
4. 是不是**审批权**没配？（审批另算，不在岗位角色里）
5. 案件是否被**隔离墙**挡住？

## 附录 C · 单人执业（独立律师 + 自己做财务）配置

1. 管理员在 `/admin/roles` 授予 `SOLE_PRACTICE_GRANTS` 组合模板
2. 在 `/admin/approval-permissions` 显式开**「本人审批例外」**
3. 归档制度必须配置
4. 注意：自己登记实收后，自己确认（需要 `finance.confirm`）

> 单人执业仍走完整流程，只是把审批人指向自己。**流程不跳过。**
