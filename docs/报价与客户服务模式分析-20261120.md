## 一、现行报价模型（从配置器还原）

参数取自 `04_律所CRM功能配置器_成本版.html`：

| 参数 | 值 | 出处 |
|---|---|---|
| 人日单价 `rate` | **2800 元/人日** | `COST.rate` |
| 人日取值 `basis` | `mid`（区间中点），可选 lo/hi | `basis === 'lo' ? lo : 'hi' ? hi : (lo+hi)/2` |
| 项目管理 `PM_RATE` | 实施人日 × **8%** | `const pm = impl * PM_RATE` |
| 上线支持 `GOLIVE_RATE` | 实施人日 × **5%** | `const go = impl * GOLIVE_RATE` |
| 私有化部署 `PRIV_DAYS` | **+12 人日** | `COST.priv ? PRIV_DAYS : 0` |
| 数据迁移 `mig` | 按迁移项累加人日 | `migTotal()` |
| 培训 `train` | 按用户数分档 | `TRAIN_DAYS[COST.users]` |
| 折扣 `disc` | 默认 0 | `COST.disc` |
| 税率 `tax` | **6%** | `COST.tax` |
| 年度维护 `MAINT_RATE` | 净价 × **18%**（再计税） | `net * MAINT_RATE * (1 + COST.tax)` |
| 测试系数 `TEST_K` | 1.15 | 常量存在，是否参与计费需在配置器界面确认 |

**计算链**

```
总人日 days = impl + pm + go + mig + train + priv
毛价 gross = days × 2800
净价 net   = gross × (1 − 折扣%)
含税 total = net × 1.06              ← 一次性交付价
年维护     = net × 18% × 1.06
三年 TCO   = total + 年维护 × 2
```

### 实际算例（mid 取值、无折扣、无迁移/培训）

**口径**：仅「功能折算人日 + 项目管理 8% + 上线支持 5%」，**不含**数据迁移、培训、私有化（+12 人日）。

| 方案 | 功能数 | 人日 | 一次性（含税） | 年维护 | 三年 TCO |
|---|---|---|---|---|---|
| P01 客户档案版 | 19 | 33.9 | **10.1 万** | 1.8 万 | 13.7 万 |
| P02 案源转化版 | 38 | 96.6 | 28.7 万 | 5.2 万 | 39.0 万 |
| P04 客户+案件版 | 69 | 223.7 | **66.4 万** | 12.0 万 | 90.3 万 |
| P05 交付协同版 | 54 | 184.2 | **54.7 万** | 9.8 万 | 74.3 万 |
| P07 全流程版 | 117 | 411.9 | **122.3 万** | 22.0 万 | 166.3 万 |
| P13 集团多分所 | 129 | 470.6 | **139.7 万** | 25.1 万 | 190.0 万 |

**另需叠加**（配置器按勾选项加）：
- 私有化部署 **+12 人日**（约 +3.6 万含税）
- 数据迁移：按迁移项累加（`migTotal()`）
- 培训：按用户数分档（`TRAIN_DAYS[users]`）
- 折扣：`COST.disc`

> 实际报价以配置器勾选结果为准；上表是**同口径可比**的基准，用于横向看方案量级。

### 合同六条（`13_商用化落地方案` §6.2）

① 数据所有权归律所，厂商无访问权，运维需审批留痕
② 知识产权：软著归厂商（含对开源改造），定制部分单独约定
③ 开源声明：包含 MIT 组件，已履行许可义务，不承担上游责任
④ 免责范围：不承担律师执业结果责任
⑤ 数据导出：终止合同时客户可导出全量（已有卷宗导出），避免锁定
⑥ 保密与竞业：实施人员保密义务 + 同区域竞业限制（如需）

## 二、与同行业四种模式的对比

| 模式 | 代表产品 | 价格形态 | 你现在的状态 |
|---|---|---|---|
| **SaaS 订阅** | 销售易、纷享销客、HubSpot、Zoho | 800–3000 元/坐席/年 | ❌ 不是（自部署、单租户） |
| **私有化买断 + 维保** | 用友、金蝶、传统 ERP | 10–50 万一次性 + 15–20% 年维护 | 🟡 维护率像，但价格形态不同 |
| **项目制人日** | 系统集成商、定制开发 | 人日 × 2000–4000 | ✅ **实质是这个** |
| **开源 + 订阅服务** | GitLab、Odoo、ERPNext、Metabase | 软件免费，收实施 / 支持订阅 | 🟡 **底子在（MIT），但没走这条路** |

**结论**：LawLink 目前是「**项目制人日 + 18% 年维护**」的混合，**不是产品定价**。

## 三、三个结构性错配（本文的核心）

### 错配 1 · 卖的是实施，不是产品

2800 元/人日 是**外包人力价**，不是软件产品价。它意味着每一单的成本与交付量线性绑定。

**如果真是产品**，第二个客户的实施人日应显著下降。按复用情景测算（实施人日降到 60%，pm/go 联动，迁移培训不变）：

| 方案 | 首客户 | 复用后（60%） | 降价空间 |
|---|---|---|---|
| P04 | 223.7 人日 / 66.4 万 | 134.2 人日 / **39.8 万** | −40% |
| P05 | 184.2 人日 / 54.7 万 | 110.5 人日 / **32.8 万** | −40% |

> 口径同上（不含迁移/培训/私有化）。

> **若第二个客户仍报 66 万，说明第一个客户的钱里有一部分是「学习成本」转嫁给了客户。**
> 这在项目制里常见，但会被有经验的客户问到。

### 错配 2 · 报价按 100% 功能算，交付只有 63%

按《能力评估》：P04 覆盖 **63%**、P05 **66%**、P08 **66%**、P07 **51%**。

而报价是按该方案的**功能要求数**折算人日的。中间的差额是：
- 要么客户付了 100% 的钱拿到 63% 的功能（信任风险）
- 要么实施时额外做人日（报价失效，需变更单）

**缺的恰恰是高频项**：客户分级、生命周期、批量导入、排期冲突检测。这些不是「锦上添花」，
是客户上手第一周就会碰到的。

### 错配 3 · 收 18% 年维护，但没有维护体系

18% 是**成熟软件行业**的维保率，它购买的是：版本升级、缺陷修复 SLA、安全补丁、技术支持响应。

现状对照：

| 维保应包含 | 现状 |
|---|---|
| 版本升级 | 有（`deploy.sh`），但**有破坏性迁移**，须先备份 |
| 缺陷修复 SLA | 无承诺 |
| 安全补丁 | 无节奏（依赖上游，`npm audit` 靠人工跑） |
| 技术支持响应 | 无 SLA，无工单系统（门户未建） |
| 服务报告 | 无 |

> **收 18% 但交付的是「有事找我」，这是最容易被客户在第二年砍掉的一项。**

## 四、客户服务现状 vs 行业标准

| 环节 | 现状 | 行业标准 | 差距 |
|---|---|---|---|
| 部署 | `deploy.sh` + 手工文档（含已知 `apk add` 卡死需重试） | 一键脚本 / 托管部署 | 中 |
| 首次配置 | 六步文档 | 实施顾问陪跑 + 验收清单 | 中 |
| 升级 | 有破坏性迁移，须 `backup.sh` 前置 | 平滑升级或厂商代升级 | **大** |
| 支持渠道 | 文档 + 直接联系 | 工单系统 + SLA 分级 | **大** |
| 问题追踪 | 无系统 | 工单看板，客户可见进度 | **大** |
| 培训 | 有手册（操作手册/培训手册），无交付物与考核 | 分层培训 + 考核 + 上线陪跑 | 中 |
| 服务报告 | 无 | 月度/季度服务报告 | **大** |
| 客户自助 | 无门户 | 客户门户看进度/账单/提问 | **大**（已在规划 S1–S3） |

## 五、三个方向与推荐

| 方向 | 做法 | 优点 | 代价 / 前置条件 |
|---|---|---|---|
| **A. 承认是实施商** | 保持人日制，把 P01/P05 做成标准包，压到 30–80 人日 | 见效快，不改商业模式 | 需要先沉淀「可复制实施方法论」，否则永远一单一议 |
| **B. 开源 + 订阅** | 软件免费自部署；收年度订阅（含升级/SLA/工单/月报），价格锚定席位或年费 | 与 MIT 定位一致；收入可预测 | **必须先建支持体系**（工单、SLA、版本节奏）——现在全部没有 |
| **C. 混合（推荐）** | 基础版免费自部署（P01 范围）；进阶版收订阅；实施另计 | 兼顾获客与收入；开源定位兑现 | 需要清晰的**功能分层边界**，且要先有门户才能提供「服务」这个商品 |

### 为什么推荐 C

1. **MIT + 自部署的定位**本来就不该靠卖软件许可赚钱，但现在的报价把软件价值也折算进人日了
2. **P01 范围（19 项）免费自部署**能带来真实用户 → 实施线索
3. **订阅必须有可交付的服务内容**，而服务内容的载体是**客户门户 + 工单 + SLA**——正是产品计划里的 S1–S3

### C 方案的价格锚点建议（待验证，不是定论）

| 层 | 内容 | 价格形态 |
|---|---|---|
| 社区版 | P01 范围，自部署，无 SLA，社区支持 | **免费** |
| 专业版 | P04/P05 范围，含升级服务 + 工单 + 8×5 响应 | 年订阅（按机构规模分档，避免按席位引起抵触） |
| 企业版 | P07/P08 范围，含私有化 + SLA + 季度服务报告 + 定制余额 | 年订阅 + 实施人日 |

> **不按席位收费的理由**：律所律师流动大，按席位会让客户在招人季抗拒续费。

## 六、分阶段落地（与产品计划对齐）

| 阶段 | 商务侧动作 | 技术侧前提 |
|---|---|---|
| 现在 | 对存量客户**按人日制**继续，但在合同里写清「功能范围以清单为准」 | — |
| S1 后 | 开始对新增客户提供「实施 + 首年订阅」打包 | 门户身份/登录可用 |
| S2 后 | 订阅可交付（客户能自助看进度/账单） | 只读视图上线 |
| S3 后 | 可承诺 SLA（工单有时限） | 工单与满意度上线 |
| S4 后 | 可评估「社区版免费」是否成立 | 获客模块（可选） |

**关键约束**：**在 S3 之前不要卖订阅**——收了订阅费但没有工单和 SLA，等于把错配 3 放大。

## 七、需要你拍板的问题

1. **现行报价是否继续对存量客户执行？**（我倾向：继续，但补功能范围附件）
2. **是否接受「第二个客户降价 40%」？** 若不接受，说明成本结构没变，需要解释给客户
3. **18% 维护费要不要先降到 12–15%，同时明确「不含 SLA」？** 或反之，先建 SLA 再维持 18%
4. **社区版边界定在 P01（19 项）还是更小？**
5. **是否愿意为「服务能力」投入**（工单系统 + SLA 流程 + 月报模板）——这是订阅制的前置成本

## 八、本文的不确定性（如实声明）

1. **成本侧完全缺失**：我只看到**售价侧**参数（2800/人日、18%），不知道你的人日成本，
   因此无法算毛利率与盈亏平衡点。**任何毛利结论都是猜的，所以本文不写毛利。**
2. **`TEST_K = 1.15` 的用途未确认**：常量存在，是否参与计费需在配置器界面核对。
   若参与，本文所有算例需上调 15%。
3. **P02 等方案的迁移/培训人日未逐项重算**，实际报价以配置器勾选结果为准。
4. **行业价格区间是公开信息的粗估**，未做逐家核价。
5. **「第二客户降价 40%」是情景测算，不是承诺**——它取决于实施方法论的沉淀程度。
