## 一、第一次使用

### 1.1 登录
用管理员发给你的邮箱与初始密码登录。首次登录后立即在 **设置 → 个人资料** 改密码。

### 1.2 你需要先知道的三件事

| 概念 | 含义 | 为什么重要 |
|---|---|---|
| **系统管理员 ≠ 业务权限** | 超管能配系统，但看不到案件、财务 | 不要以为当上超管就什么都能看 |
| **审批权是独立的** | 能不能审批某类事项，由「审批权限组」单独授予 | 批不了不是系统坏了，是没授权 |
| **默认禁止审批自己的申请** | 单人执业需显式开「本人审批例外」 | 一个人也要走完流程 |

### 1.3 管理员：首次配置顺序

```
管理后台 → 岗位角色          建角色、勾权限        /admin/roles
管理后台 → 团队              建团队、加人          /admin/teams
管理后台 → 审批权限组        配每类事项谁能批      /admin/approval-permissions
管理后台 → 归档制度          不配不能正式归档      /admin/archive-policy
管理后台 → 提醒维护 → 期限规则  启用诉讼时效等规则  /admin/reminders
管理后台 → 文书模板          按业务线预置文书      /admin/document-templates
```

> `/settings` 只有「个人资料」（改密码、改姓名、日历订阅重置）。**系统配置都在 `/admin`**，需要系统管理员身份。

**第 4 步不做，归档时会直接拦下**——这是硬门禁，不是提示。

## 二、日常工作流

### 2.1 主线一图

```
收案登记 → 冲突检索 → 转正式案件 → 持续跟进 → 财务记录 → 结案归档 → 数据导出
```

### 2.2 收案（`/intakes` 或顶栏「新建收案」）

1. 点顶栏 **新建收案**，填来源、联系人、初步案情、当事人
2. 提交时系统**自动带全部主体做冲突检索**，结论挂在这次收案上
3. 结论分三种：可承接 / 有冲突 / 信息不足

> **红色命中不能绕过。** 必须先解除或走审批，否则转不了正式案件。

**收案前想先自己查一下**：顶栏「冲突预检」。它**不出结论**、不能替代正式检索、页面不显示历史预检记录（留痕在审计日志里）。

### 2.3 转正式案件

在收案详情点「转为案件」。系统生成统一编号（`internalCode`），全所财务、归档都认这一个号。

**动态复核门禁**：以下三处写入会被拦，要求先重新检索并给出「已排除冲突」结论——
- 新增代理程序
- 新增委托合同
- 补充协议生效

> 这不是找麻烦：主体或代理范围变了，原来的结论就不成立了。

### 2.4 案件办理（`/matters/[id]`）

案件详情是**一屏工作台**：

```
案卷头 → 程序栏（点卡片切换） → 页签：案件档案 / 办案进程 / 委托与财务 / 审批用印
                                   侧栏：承办团队 / 最近待办 / 最近记录
```

**办案进程**：（左侧环节竖排，末尾「＋ 添加环节」）

| 操作 | 入口 | 说明 |
|---|---|---|
| 加事项 | 「＋事项」 | 任务 / 期限 / 开庭，进待办 |
| 加记录 | 「＋记录」 | 沟通 / 寄收件 / 研判，进经办记录 |
| 上传材料 | 环节操作条 | 支持多版本，改过几版看得见 |
| 改任务 | 待办行的「改」 | 改标题 / 说明 / 截止 / 优先级 |
| 改 / 删记录 | 经办记录行的「改」「删除」 | **只对自己写的记录显示** |

> **责任人不能在待办行改**。换人要走「事项责任面板」的交接流程，接收方接受后生效。这是为了留痕。

**同一数据只在一处出现**：未完成事项只在待办，已发生事项只在经办记录。

### 2.5 日程与期限（`/schedule`）

- 开庭、会议统一排期；期限按规则算（含法定休假日顺延**提示**，不替律师改日期）
- 提醒走**送达台账**：登记 → 投递 → 结果落账。能看到「该发没发」
- 「订阅日历」在右上角，可复制订阅链接到手机 / Outlook（**单向**）

### 2.6 财务（`/finance`）

**两条铁律**：

1. **实收一律两步**：任何人的实收先记「待确认」，**不生成实收、不派生分成、不计入报表**，只在「待确认实收」区显示琥珀色。由持「确认实收到账」权限的财务确认后才生效。
2. **已入账不可直接删**：更正走冲正 / 退回，保留原记录。

**开票动线**：
```
提交开票申请（关联案件须传开票依据，专票校验六要素）
   → 审批人：可直接上传电子发票+发票号一步到「已开具」
              也可先批准（待开票），再由有「执行开票」权限的人上传完成
```

**核销**：实收 → 应收，可手工分配，也可用「按最早到期自动填满」建议（生成→预览→确认）。

### 2.7 归档（`/archive`）

1. 案件详情 → 结案。系统用 `closureReady` 检查：程序是否结束、事项是否处置、保全是否解除、交接是否承接、待确认款、待审批
2. 检查通过后才能提交正式归档
3. 归档需审批（复用 `ARCHIVE_APPROVE` 规则，**排除自审批**）

> **归档即冻结**：归档后案件不可再写，关联关系、证据项都锁死。

**历史卷宗要借阅**：`/archive` → 借阅申请 → 审批 → 限时（默认 30 天）可读 → 留痕。到期自动失效。

## 三、组织与权限（管理员）

### 3.1 三层资格

| 层 | 管什么 | 谁配 |
|---|---|---|
| 系统管理员 | 系统配置、账号、岗位 | 由超管授予 |
| 业务岗位（自定义角色） | 能办什么案、看什么账 | 设置 → 岗位角色 |
| 审批权限组 | 某类事项谁能批 | 设置 → 审批权限 |

### 3.2 隔离墙（敏感业务必用）

同所内两个团队互不可见。开启后：
- 被点名的人看不到该案件（列表消失、直访 404）
- **写路径同样被挡**——读不到也改不了
- 审批工作台、工作台列表都过滤

> **已知限制（如实告知）**：通知**不按隔离墙过滤**。被隔离的人可能收到提到该案件标题的通知。敏感案件请同时关闭相关通知。

### 3.3 审计

- 所有写入留痕，**链式哈希**，管理员也改不了
- 管理后台「审计」可按对象查（加索引后 14.9ms → 3.0ms）
- 审计链完整性在后台有独立卡片，断点会指出从哪来
- 支持导出 SIEM（CEF / Syslog / JSON）

## 四、常见问题

| 症状 | 真实原因 | 怎么办 |
|---|---|---|
| 「案件不存在」 | 可能是真不存在，**也可能是被隔离/无权** | 措辞刻意统一，**不区分**——避免泄露案件存在性。找管理员确认权限 |
| 实收登记了但报表没有 | 待确认状态不计入 | 找财务确认 |
| 改不了责任人 | 设计如此 | 走事项责任面板交接 |
| 归档按钮灰的 | 归档制度未配 / 结案门禁未过 | 看门禁清单哪一项没清 |
| 批不了某个申请 | 审批权限组没授权 / 是本人申请 | 找管理员或走本人审批例外 |
| 部署时卡在 `apk add` | Docker 构建网络问题（已知） | **重试一次即可** |
| 打开页面 500 但测试全绿 | 可能是 `prisma generate` 产物被覆盖 | 重跑 `npx prisma generate` 并重启 |

## 五、安全须知（给使用者，不是给运维）

1. **证件号、电话是加密存储的**，查看会写审计。不要截图外传。
2. **导出卷宗等于把整个案卷带走**，导出有审计留痕。
3. **不要共用账号**。系统按账号记审计，共用等于审计失效。
4. **离开工位锁屏**。会话有失效机制，但不替代锁屏。
