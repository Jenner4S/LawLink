## 三、照着点的验收路径（获客 → 回款）

> 登录：`admin@lawlink.local` / `LawLink2026!Dev`（本地环境）

### ① 登记线索（`/leads`）
- 点「登记线索」，填客户名 + 手机号 + **职业/行业** + **渠道（两级）** + **团购/券金额**。
- **应看到**：线索出现在列表；若手机号与已有记录重复，弹提示「该号码可能已有人跟进」并列出对方，**但线索照常登记**（同号可能是家人代接，不硬拦）。
- **口径**：查重是归一化后比对（空格/横线/+86 都算同一个号）。

### ② 派单给律师（`/leads` 行内）
- 行内「派给律师…」选一位律师。
- **应看到**：状态变「待接单」；该律师需**本人**在行内点「接单」或「拒接」。
- **口径**：派单不会自动算「已接」；拒接**必须写理由**；拒接后不自动转派（转给谁要人判断）。
- 顶部「派单」筛选：待派单 / 待接单。

### ③ 邀约 → 到店 → 谈案（`/leads` 行内按钮）
- 「邀约」→ 阶段变「已邀约」，可填约定时间。
- 到店当天点「到店」→ 阶段「已到店」，到店结果记「已到店」。
- 到了约定时间没来 → 点「**未到店**」→ 记「爽约」，**阶段不变**（还能再约）。
- 谈完点「谈案完成」→ 阶段「已谈案」。
- **口径**：只有「已谈案」才能转收案，跳步会被拒。

### ④ 漏斗与渠道（`/leads` 顶部）
- **本月获客漏斗**：新增线索 / 已邀约 / 已到店 / 已谈案 / **爽约** / 已转收案 / 转化天数。
- **本月线索 → 回款**：线索 → 转收案 → 已签约 → 已回款；签约额 / 实收 / **回款率** / 线索→回款率。
- **按渠道**：每条线索/到店/成交 + 成交率 + 券金额 + **单条线索成本 / 单成交成本**。
- **口径注意**：
  - 「率」在分母为 0 时显示「—」，**不显示 0%**（0% 会被误读成"一个都没成"）。
  - 单位成本在未录券金额时也显示「—」，**不显示 0**（0 成本会被误读成"不花钱"）。
  - 只做成本，**不做 ROI 比率**——收入侧没有可信数据，混进来会把"线索质量"和"客单价"搅在一起。

### ⑤ 转收案 → 签约 → 回款（`/matters`、`/finance`）
- 线索行点「转收案」→ 生成收案单。
- 案件详情的「委托与财务」页签：登记合同（含**风代比例**）、登记应收与实收（两步确认）。
- **应看到**：实收需确认；未确认的「待确认到账」不计入已收。
- **风代计提**：只有已签署且设了比例的合同才出现，金额按**回款 × 比例**推算，界面标注「以结算单为准」。
- **坏账**：申报 → 由**他人**（财务/合伙人）批准；**不能自批**；只有已批准才扣减未收余额，且**不改写应收发生额**。

### ⑥ 报表（`/reports`）
- 客户应收表新增「**已批坏账**」列，余额已按同口径扣减（与案件页一致）。

## 四、三个可自助切换的业务口径（`/leads` → 「渠道与口径」）

| 口径 | 可选值 | 当前默认 | 默认理由 |
|---|---|---|---|
| 风代计提基数 | 按回款 / 按合同额 | **按回款** | 风代后收费，钱到手才有得提 |
| 团购/券金额归属 | 成本侧 / 收入侧 / 只记录 | **成本侧** | 「团购券」通常是律所付平台的投放成本 |
| 坏账阈值分级审批 | —— | 统一双人审批 | 更严不会更松；分级需可配置阈值，收益不抵复杂度 |

**切换只改解读，不改历史数据**；改配置即可，不用改代码、不用重新部署。

## 五、明确不做的两件事（附理由，避免以后反复讨论）

1. **通用多维表格能力**（自定义视图 / 公式列 / 冻结列）
   —— 那是产品形态差异。你用宽表是因为当时没有领域模型可用；LawLink 的价值恰在模型（审批链、两步确认、核销、权限墙）。替代方案：既有案件自定义字段。
2. **渠道 ROI 比率**
   —— 缺收入侧可信数据。已给单位成本（单线索 / 单到店 / 单成交），这三项能直接支撑"钱往哪投"的判断。
