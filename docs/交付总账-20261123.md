# 交付总账（2026-11-23）

> 一句话：**获客 → 邀约 → 到店谈案 → 签约 → 回款**这条链在系统里连成了一条，
> 每一步都能点到、能查到数、有验证证据；剩下的事大多在**你那一侧**（两个口径决策 + 三项外部输入）。

---

## 一、交付了什么

### 1. 全链路（按客户实际动作顺序）

| 环节 | 系统里能做什么 | 验证 |
|---|---|---|
| 获客 | 登记线索（来源/渠道/手机号查重提示）、派单、接单 | 金线 ①②③ |
| 邀约 | 约定上门时间 → 自动进「未来 7 天待上门」 | 金线 ④⑭ |
| 到店 | 到店/爽约分别记，爽约**不改阶段**只留痕 | 金线 ⑤⑥ |
| 谈案 | 谈案完成 → 进「已谈案未转收案」积压，超 3 天按等待天数排序，**每条可一键催办** | 金线 ⑦⑮⑯ |
| 签约 | 转收案（有限制：未谈案不能转） | 金线 ⑧、反例已覆盖 |
| 回款 | 结算单 → 实收 → 应收核销；坏账逐笔冲抵（FIFO + 行锁） | `lead-to-cash`、`writeoff-items` 15 例 |

### 2. 渠道这条线（决定钱往哪投）

结构（两级、停用不删除）→ 归因（每线索挂渠道）→ 下钻（点渠道看线索，一级含子渠道）
→ 成本（月投放录入，填 0 = 没投）→ 补录（近 12 月）→ 判断（成本环比 ↑↓%、成交率环比 ▲▼）。

### 3. 管理口径（都可自助配置，不用改代码）

| 项 | 默认 | 谁能改 |
|---|---|---|
| 风代计提基数 | 按回款 | 管理员/合伙人 |
| 券金额归属（成本侧/收入侧/忽略） | 成本侧 | 同上 |
| 坏账自批上限 | **0（永不自批）** | 同上 |
| 列表显示哪些列 | 全显 | 同上（线索人列不可隐藏） |
| 渠道月度投放成本 | 空 | 同上（面板内直接填） |

## 六、已知边界（**不是缺陷**，是明确取舍）

- 同号查重**只提示不阻断**（老客户换号/家人共用号很常见，硬拦会逼人乱填）
- 渠道**只两级**（三级以上没人维护，报表会碎）
- 爽约**不自动重排**（要不要再约是人的判断）
- 风代**只存比例**、金额读时派生（金额落库就会和回款不一致）
- 坏账**只减可核销额、不减应收金额**（应收是事实，坏账是处置）
- 报表「率」在分母为 0 时显示「—」，**不显示 0%**（0% 会被读成"没人来"）
- 坏账**已全额结清的案件拒绝登记**（不让账目说谎）
- 审计表**禁删、无自动归档**（等第五节的决策）
- cron 是**进程内**调度，单实例成立；多副本需数据库租约（未做）
