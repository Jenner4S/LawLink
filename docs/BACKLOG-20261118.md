## 2. P0-1 工时与费率：设计

### 2.1 为什么这是 P0

LawLink 现在只记「结果」——收了多少钱；不记「投入」——花了多少小时。后果：

- 算不出单案毛利（不知道成本）
- 算不出律师产能（不知道谁在干活）
- 报价没有依据（不知道同类案件要投入多少）
- **计时收费的所根本用不了**（商事、非诉、涉外）

LexNebulis 有 `time_entries` / `rate_schedules`，LawLink 一张都没有。

### 2.2 数据模型

```prisma
/// 费率：四级覆盖，就近优先（案件 > 客户 > 个人 > 角色 > 默认）
model RateSchedule {
  id            String   @id @default(cuid())
  /// 适用范围：MATTER / CLIENT / USER / ROLE / DEFAULT
  scope         RateScope
  matterId      String?
  clientId      String?
  userId        String?
  role          UserRole?
  /// 标准小时费率（元/小时）
  hourlyRate    Decimal  @db.Decimal(12, 2)
  /// 计费单位（分钟），不足进位。0 = 按实际分钟
  billingIncrement Int   @default(0)
  effectiveFrom DateTime
  effectiveTo   DateTime?
  note          String?
  active        Boolean  @default(true)
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  timeEntries   TimeEntry[]
  @@index([scope, active])
  @@index([matterId])
  @@index([userId])
}

/// 工时记录
model TimeEntry {
  id            String   @id @default(cuid())
  matterId      String
  matter        Matter   @relation(...)
  userId        String
  user          User     @relation(...)

  workDate      DateTime @db.Date
  minutes       Int
  narrative     String   @db.Text          // 工作内容（律师可读）
  taskCode      String?                    // 自定义任务分类，如 阅卷/开庭/起草
  billable      Boolean  @default(true)
  noChargeReason String?                   // 不可计费时必填

  /// 费率快照：录入当时锁定的费率，不随费率表变动而变
  rateScheduleId String?
  rateSchedule   RateSchedule? @relation(...)
  hourlyRateSnapshot Decimal @db.Decimal(12, 2)
  amount        Decimal  @db.Decimal(12, 2)

  /// 出账关联：工时被哪张账单收走
  billingId     String?
  billing       Billing? @relation(...)

  status        TimeEntryStatus @default(DRAFT)
  approvedById  String?
  approvedAt    DateTime?

  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  @@index([matterId, workDate])
  @@index([userId, workDate])
  @@index([status])
}

enum RateScope { DEFAULT ROLE USER CLIENT MATTER }
enum TimeEntryStatus { DRAFT SUBMITTED APPROVED BILLED WRITTEN_OFF }
```

### 2.3 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 费率是否快照 | **是**，`hourlyRateSnapshot` | 费率上调后，历史工时的金额不能跟着变——否则已出账的账目会漂移 |
| 计费单位 | 支持 `billingIncrement`（如 6 分钟 = 0.1 小时） | 律所惯例按 0.1h 进位；不做的话算出来的金额与账单对不上 |
| 不可计费工时 | 允许，但必须填理由 | 无理由的不可计费 = 变相藏工作量，管理上要能看出来 |
| 与 Billing 的关系 | 工时**可**挂到 Billing，但不强制 | 计时所会挂；按标的收费的所只用工时算成本，不挂账单 |
| 审批 | 默认 DRAFT，可配置是否要审 | 小所不需要审批，大所要防止乱填 |

### 2.4 分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1-a | schema + 迁移 + 费率 CRUD + 工时录入/编辑 | 能录一条工时并算出金额 |
| 1-b | 案件详情「工时」页签 + 汇总（已投入/折算/已收） | 单案三角可见 |
