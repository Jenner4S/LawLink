# AuditLog 分区方案可行性验证（2026-11-22）

> 目的：`AuditLog` 有触发器禁删、却没有归档路径（有政策、无实现）。
> 正解是分区表 + 老分区 DETACH，但那要重建表结构。
> **在没量过之前不动主库**——本文件是演练实测结果，不是估算。

## 一、结论先说

**技术可行，且停机窗口不是障碍**（24 万行全流程 **约 3 秒**）。
真正的成本在两处，都可控：

| 项 | 结论 | 代价 |
|---|---|---|
| 运行时兼容性 | ✅ **完全正常** | `create` / `findFirst` / `count` / 按对象 `findMany` 在分区表上实测全部正确 |
| Prisma 零漂移门禁 | ✅ **仍成立**（`migrate diff` 输出 empty migration） | 无 |
| 主键语义 | ⚠️ **必须改为 `PRIMARY KEY (id, "createdAt")`** | 代码里 **0 处** `auditLog.findUnique({id})`，故无调用点要改；但 schema 需写 `@@id([id, "createdAt"])` |
| 迁移方式 | ⚠️ 必须手写 SQL migration | Prisma 不支持声明式分区 DDL，`migrate diff` 生成不了；需自写 SQL + 改名交换，并纳入既有迁移纪律（演练 → 主库 → 不变量） |

## 三、演练中撞到的三个真实坑（都已写进脚本注释）

1. **分区表的主键必须包含分区键**
   `PRIMARY KEY (id)` 直接报错：
   `unique constraint on partitioned table must include all partitioning columns`。
   只能 `PRIMARY KEY (id, "createdAt")`。

2. **`SELECT *` 会错位**
   原表**物理列顺序**与 schema 声明顺序不一致（实测 `createdAt` 在第 9 位，
   schema 里在末尾），导致 `INSERT INTO ... SELECT *` 报
   `column "createdAt" is of type timestamp but expression is of type text`。
   必须写**显式列名**。

3. **列类型必须逐字一致**
   Prisma 的 `DateTime` 映射为 `timestamp without time zone`；
   我第一版写成 `timestamptz` → 类型不匹配。分区表不是新设计的机会，
   是**原表的搬家**，类型必须原样。

另修一处脚本自身缺陷：`$变量` 紧跟全角字符会被 bash 吞进变量名
（与 `mutation-check` 的 S1 探针同源），已统一改 `${变量}`。

## 四、建议的执行顺序（等决策后照此做）

1. 临时库演练（`./scripts/drill-audit-partition.sh`，秒级，可反复）
2. 写手写 migration SQL：建父表 + 分区 + 索引 + 触发器 → 改名交换
3. schema 改 `@@id([id, "createdAt"])`，跑 `check-doc-numbers` 确认零漂移仍成立
4. 主库迁移三件套：`pg_dump` 备份 → 临时库演练 → 主库执行 → `verify-db-invariants`
5. 老分区归档：`DETACH` → 导出（既有 `/api/audit/export`）→ 移入冷存储
6. cron 加「保留 N 个月后自动 DETACH」（复用 `retention.ts` 的可配置模式）

## 五、不做的事（避免误读）

- **未改主库任何结构**；演练全程在 `lawlink_drill_*` 临时库，结束即 DROP（残留 0 已核）；
- **未提交迁移文件**（决策前不落 schema 变更）；
- **未做 `DETACH` 后的自动归档流程**（那是第 5–6 步，属决策后的实施）。

## 六、需要你决定的一件事

| 选项 | 影响 |
|---|---|
| **继续 C（仅导出，零风险）** | 审计表继续增长，一年约 150–200MB；证据可通过既有接口带走 |
| **推进 A（分区）** | 彻底解决增长，整改成本：1 次手写迁移 + `@@id` 变更 + 一次预约的迁移窗口（实测秒级，但需备份与复核） |

我的建议：**现在留 C，等审计行数过 50 万再说**。理由是当前量级（1073 行测试期）离压力线很远，
而改主键语义虽然调用点为 0，仍是全表级改动，不值得为"可能一年后才需要"的性能买单。
