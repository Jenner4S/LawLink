# 外部对接说明（2026-11-23）

> 三项外部输入里，**表单入站已经做完**——业主拿到地址就能用，不需要凭据也不需要开发。
> 另外两项（IMAP 收件、短信/微信通道）当前是「配置即有、未配置则跳过」，理由写在下面。

## 一、官网 / 公众号表单入站（**已完成，可直接用**）

### 怎么接

1. 在服务器 `.env` 里设一个随机串：
   ```
   INBOUND_LEAD_TOKEN=<openssl rand -hex 24 的输出>
   ```
2. 重启应用。
3. 表单提交地址指向：
   ```
   POST https://<你的域名>/api/inbound/lead
   Content-Type: application/json
   x-inbound-token: <上面那个随机串>
   ```

### 请求体

```json
{
  "name": "张三",
  "phone": "13900001234",
  "channelName": "大众点评",
  "externalId": "表单侧自己的提交id",
  "message": "想咨询离婚财产分割",
  "pageUrl": "https://www.example.com/consult"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | ≤40 字 |
| `phone` | — | 手机号格式；错格式会被拒（400 并指出哪一项） |
| `channelName` | — | 按名匹配**已启用**渠道；匹配不到只是不挂渠道，**不因此拒单** |
| `externalId` | — | 表单侧提交 id，**用于幂等**（同 id 重复提交只建一条） |
| `message` | — | 客户留言，落到线索备注 |
| `pageUrl` | — | 来源页，落到 `sourceDetail` |

### 响应

| 状态 | 含义 |
|---|---|
| 201 | 创建成功，返回 `{ ok, id, duplicate: false }` |
| 200 | 同 `externalId` 已存在，返回 `{ ok, id, duplicate: true }`（**不会重复建**） |
| 400 | 字段校验失败，`issues` 里写明哪一项 |
| 401 | token 缺或错 |
| 429 | 同一 IP 每分钟超过 60 次 |
| 503 | 未配 token，或系统里没有可用的接收人（响应带 `howTo`） |


### 接的时候注意一件事（我真踩过）

新加公开接口时，`src/proxy.ts` 的 matcher 必须把它排除，否则外部请求会被 **307 重定向到 `/login`**。

我这次的实测过程：单测 8 例全绿、`tsc`/`eslint`/`build` 全过，**线上 curl 一打是 307**。
原因是 route 单测直接 import `POST` 函数调用，**绕过了 Next 中间件**。

症状会是「表单提示提交成功，但系统里没有线索」——比报错更难查。

已做两件事防它再发生：
1. `src/proxy.ts` 里写明这条教训；
2. 新增门禁步骤「公开接口一致性」：自动找出「自带 token 鉴权且不依赖员工会话」的 API 路由，
   检查是否都在 matcher 排除列表里。变异验证过（从 matcher 移除 `api/inbound` → 该步变红）。

### 落库后的效果

- 阶段 `LEAD`、来源 `ONLINE`、`assigneeStatus = UNASSIGNED` → **自动进「待派单」视图**，值班人一眼能看到；
- 同时写一条跟进记录「官网表单提交（自动入站）」+ 一条审计。

### 两条明确的取舍

1. **未配置 token 时返回 503，不静默放行**——否则公网任何人都能往你的库里造线索。
2. **没有 `externalId` 就不做去重**。按"同手机号 24 小时内"去重会吞掉真实重复咨询（同一个人上午问一次、下午再问一次是两件事）。要去重请在表单侧带 `externalId`。

### 限流的局限（如实说）

应用层是**单实例内存令牌桶**（每 IP 60 次/分钟）。多副本部署时窗口各自算。
真要抗刷应放在网关/WAF，应用层这层只是兜底。

## 二、邮件：发件已通，收件（IMAP）未做

| 能力 | 状态 | 说明 |
|---|---|---|
| 发件（SMTP 提醒） | ✅ 已有 | 配 `SMTP_HOST` / `MAIL_FROM` 即生效；未配置时**跳过发送不报错**（队列记"跳过"） |
| 收件（IMAP 拉取） | ❌ 未做 | 需要邮箱凭据 + 选文件夹/标记规则；当前来件靠**站内短信解析**与手工上传 |

**现在的进度（2026-11-23 更新）**：已把「邮件 → 线索」这一层做完并测好，
只差协议层最后一步：

| 部分 | 状态 |
|---|---|
| 邮件 → 线索草稿（姓名/手机号抽取、正文压行截断、`messageId` 作幂等键） | ✅ 已实现，5 例测试 |
| 批量收件入库（单封失败不中断整批、无接收人时提前停、`since` 过滤） | ✅ 已实现，3 例测试 |
| 来源适配层 `MailSource` + `FakeMailSource`（可测） | ✅ 已实现 |
| **真 IMAP 拉取** | ❌ 未接：需装 `imapflow` 并在 `createImapSourceFromEnv` 里实现 |

**一个刻意的设计**：凭据配齐但实现没接时，应用**明确抛错**说明还差什么，
而不是静默返回空数组——静默失败会让「没收到线索」长期无人发现。

**还需要你定的**：哪些邮件算"咨询线索"（例如只认某个收件地址 / 主题含"咨询"），
以及拉取频率。这属业务规则，不是技术选择。

## 三、短信 / 微信通道：模板与开关就绪，通道未接

| 能力 | 状态 |
|---|---|
| 站内提醒、到期提醒、周报 | ✅ 已有（站内 + SMTP） |
| 对外发短信 / 微信 | ❌ 未接通道 |
| 来件短信解析归档 | ✅ 已有（`sms/` 模块，含附件归档到案件） |

**为什么没先做**：没有服务商密钥无法联调；且发出去的内容涉及对客户的正式通知，
模板文案应经你确认（现在系统里的提醒文案是站内口径，不一定适合直接发给客户）。

## 四、小结：你现在要做的

| 事项 | 你要做什么 | 之后系统会怎样 |
|---|---|---|
| 官网表单 | 配 `INBOUND_LEAD_TOKEN` + 表单指向 `/api/inbound/lead` | 线索自动进「待派单」 |
| IMAP 收件 | 给邮箱凭据 + 说明"哪些邮件算来件" | 我按 `sms/` 框架接 |
| 短信/微信 | 给服务商密钥 + 确认对外文案 | 提醒可走短信/微信 |
