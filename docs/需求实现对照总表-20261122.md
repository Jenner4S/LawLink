## 一、P0（不做就替代不了他现在那张表）

### P0-1 渠道两级 + 投放金额
- **需求来源**：截图 A 组「渠道 / 二级渠道 / 团购金额」；推断用途是决定钱往哪投
- **实现位置**：`LeadChannel`（自引用两级）+ `Lead.channelId` + `Lead.voucherAmount`
  - 服务：`src/server/leads/channels.ts`、`channels-actions.ts`（增/停，**停用不删除**）
  - 聚合：`src/server/leads/analytics.ts` → `byChannel`（含单线索/单到店/单成交成本）
  - 界面：`/leads` → 「渠道与口径」面板 + 「按渠道」表
- **验证**：`lead-channels.test.ts`（7 例）、`lead-channel-roi.test.ts`（4 例）；金线实测读到
  「探针投放 / 探针平台 | 2 / 1 / 0 | 0% | ¥2400 | ¥1200 / —」
- **边界**：只做两级；单位成本只算成本**不做 ROI 比率**（缺收入侧可信数据）；券金额归属可配置（默认成本侧）

### P0-2 手机号查重
- **需求来源**：截图 A 组「联系方式-是否重复」
- **实现位置**：`src/server/leads/phone.ts`（`normalizePhone` / `findPhoneDuplicates`）
  - SQL 侧归一化：`right(regexp_replace(phone,'[^0-9]','','g'), 7)`
  - 调用：`createLead` 返回 `duplicates`；`listLeads` 返回 `phoneDuplicateCount`
  - 界面：`/leads` 重复徽标 + 登记时 toast 提示
- **验证**：`lead-phone-dedupe.test.ts`（9 例，含带空格号码）
- **边界**：**只提示不阻断**（家人代接/总机转接是真实场景）；跨线索/客户/收案三实体比对

### P0-3 到店三态 + 爽约
- **需求来源**：截图 B 组「到店来访 = 未曾来访」；推断「约了没来」与「没约」是两个问题
- **实现位置**：`Lead.visitOutcome`（PENDING / ARRIVED / NO_SHOW）
  - 动作：`addLeadActivity` 按类型同步（INVITE→PENDING、VISIT→ARRIVED+visitedAt、NO_SHOW→NO_SHOW）
  - 聚合：`analytics.ts` 的 `noShow` / `noShowRate`
  - 界面：`/leads` 行内「未到店」按钮 + 爽约徽标
- **验证**：`leads.test.ts`；金线第⑥步实测「已到店后『未到店』按钮不出现」
- **边界**：**爽约不推进阶段**（可再约）；不自动重排下一次邀约

### P0-4 风险代理结构化
- **需求来源**：截图 C 组「风代比例 / 风代金额」
- **实现位置**：`Billing.contingencyPercent` + `src/server/finance/contingency.ts`
  - **金额不落库**，读时派生；基数**可配置**（`settings/lead-finance-policy.ts`，默认按回款）
  - 界面：案件详情「委托与财务」的风代明细块，标注「以结算单为准」
- **验证**：`finance-contingency.test.ts`（9 例）、`lead-finance-policy.test.ts`（7 例）
- **边界**：非风代案件不显示该块；比例变更留审计；基数切换不改历史数据

### P0-5 坏账登记
- **需求来源**：截图 C 组「退款及无法收取费用差额」
- **实现位置**：`ReceivableWriteOff` + `src/server/finance/writeoff-actions.ts`
  - 申报 → **他人**审批（不能自批）→ 只扣未收余额、**不改写应收发生额**
  - 报表对齐：`src/server/reports/writeoff-align.ts`（只算 APPROVED）
  - 界面：案件详情坏账块 + 报表「已批坏账」列
- **验证**：`finance-writeoff.test.ts`（9 例）、`reports-writeoff.test.ts`（5 例）
- **边界**：**未做金额阈值分级**（建议保持双人审批）；**未做与 `Allocation` 逐笔对应**

## 四、明确不做（附理由，避免以后反复讨论）

| 项 | 理由 | 替代 |
|---|---|---|
| 通用多维表格（自定义视图/公式列/冻结列） | 产品形态差异：LawLink 的价值在模型（审批链、两步确认、核销、权限墙），追平表格灵活性等于放弃模型优势 | 既有 `custom-fields` + 列显隐 |
| 渠道 ROI 比率 | 缺收入侧可信数据；混入客单价会把「线索质量」搅浑 | 已给单线索/单到店/单成交成本 |
| 坏账金额阈值分级审批 | 更严不会更松；阈值分级需可配置 + 更多测试，收益不抵复杂度 | 统一双人审批 |
| 审计自动归档（暂时） | 分区方案实测可行（24 万行 3 秒）但当前量级离压力线很远 | 既有 `/api/audit/export` 导出取证 |
